# 内置流程

> 来源：ecd/docs/ERB_Internal_Process（ERB 的内置流程）、ecd/docs/Flow（流程图）、ecd/docs/EraBasic_Structure（EraBasic 的结构）；zh 套件 Flow.md 交叉核对；源码 `Runtime/Script/Process.SystemProc.cs`、`Runtime/Script/Process.cs`、`Runtime/Script/Process.State.cs`、`Runtime/Script/Process.ScriptProc.cs`、`Runtime/Script/Statements/Variable/VariableEvaluator.cs`。

## 概述

Emuera 内部有一套固定的游戏流程状态机，由 `SystemStateCode` 枚举与 `systemProcessDictionary` 分发表实现。引擎在状态机的特定节点自动调用名字固定的「框架函数」（`@SYSTEM_TITLE`、`@EVENTTRAIN`、`@SHOW_SHOP`……），脚本要做的就是把逻辑填进这些函数。流程之间用 `BEGIN` 命令切换。本篇给出每个阶段的内置处理顺序与系统函数调用约定。

## 状态机与主循环

`Process.DoScript` 是整个游戏的心跳（`Runtime/Script/Process.cs:330-359`）：脚本执行（`runScriptProc`）与系统流程（`runSystemProc`）交替进行——脚本把 `functionList` 跑空后交还系统状态机，状态机推进到某个「调用框架函数」的状态后又进入脚本执行。状态→处理函数的映射在 `initSystemProcess` 一次性注册（`Runtime/Script/Process.SystemProc.cs:19-78`），`runSystemProc` 直接查表调用（`Runtime/Script/Process.SystemProc.cs:89-101`）。

系统调用脚本函数只有一条途径：`callFunction(name, force, isEvent)`（`Runtime/Script/Process.SystemProc.cs:151-168`）——`isEvent=true` 走事件函数的多重定义链，`force=false` 时函数未定义则返回 `false` 由状态机自行跳过，`force=true` 时未定义直接抛错（必须存在的框架函数如 `@SHOW_STATUS`、`@USERCOM` 都以 force=true 调用）。

关键状态码（`Runtime/Script/Process.State.cs:17-78`）带两个标志：`__CAN_BEGIN__`（此处可执行 `BEGIN`）、`__CAN_SAVE__`（此处可呼出存读档界面）。`Normal` 状态两者皆有；`Train_CallEventCom` 之前的训练状态不可 BEGIN（也就是训练中途的多数状态禁止直接 `BEGIN SHOP`）。

| `@EVENTFIRST` | `First_Begin`（`BEGIN FIRST` / 新游戏） | 是 | 新游戏初始化、开场 |
| `@EVENTSHOP` | `Shop_Begin`（`BEGIN SHOP`） | 否 | 商店（主界面）开始处理 |

| `@USERSHOP` | `Shop_WaitInput`，输入超出 0–99 | 是 | 处理自定义商店选项 |
| `@EVENTBUY` | `Shop_CallEventBuy`，购买成功 | 否 | 购买后处理 |

| `@USERCOM` | `Train_WaitInput`，输入不是可选指令 | 是 | 处理自定义指令 |
| `@EVENTCOM` | `Train_CallEventCom`，选中指令后 | 否 | 指令前置事件 |
| `@COMxx` | `Train_CallComXX` | 是 | 指令本体 |
| `@SOURCE_CHECK` | `Train_CallSourceCheck`，`@COMxx` 返回非 0 | 是 | 参数结算 |
| `@EVENTCOMEND` | `Train_CallEventComEnd`，结算后 | 否 | 指令收尾 |
| `@EVENTEND` | `AfterTrain_Begin`（`BEGIN AFTERTRAIN`） | 是 | 结束训练、结算 |

源码中的判定名单见 `IdentifierDictionary.IsEventLabelName`（`Runtime/Script/Data/IdentifierDictionary.cs:54-70`，9 个 EVENT 函数）与 `IsSystemLabelName`（`Runtime/Script/Data/IdentifierDictionary.cs:71-110`）。注意：**`@CALLTRAINEND` 不在事件函数名单中**，不能多重定义；带 `EVENT` 前缀的 9 个都是事件函数，可多重定义、全部按 `#ONLY/#PRI/#LATER` 分组执行（见 language/ERB结构与函数.md）。

## BEGIN 与流程切换

`BEGIN` 的运行时行为（`Runtime/Script/Statements/Instraction.Child.cs:3044-3053` 与 `Runtime/Script/Process.State.cs:181-318`）：

```text
// Process.State.cs:208-239, 270-318（伪代码）
SetBegin(keyword, force):                       // BEGIN 命令
    keyword ∈ {SHOP, TRAIN, AFTERTRAIN, ABLUP, TURNEND, FIRST, TITLE}
    否则抛 InvalidBeginArg
    非 TITLE 时：当前 SystemState 必须带 __CAN_BEGIN__，
    否则抛 CanNotUseInstruction（「该状态不能 BEGIN」）      // :220-225
    begintype = type
Return() 使 functionList 退空且 begintype != NULL:
    Begin():                                    // :270
        begintype → 对应 *_Begin 状态码          // :276-306
        清空 functionList（丢弃全部返回地址 —— BEGIN 不返回）
        begintype = NULL
```

| 关键字 | 目标状态 | 备注 |
| --- | --- | --- |
| `BEGIN TITLE` | `Title_Begin` | 任何状态都可用（1.729 起） |
| `BEGIN FIRST` | `First_Begin` | 清空资源缓存后进入 |
| `BEGIN SHOP` | `Shop_Begin` | 从 `Normal` 进入时会触发自动存档 |
| `BEGIN TRAIN` | `Train_Begin` | 先做变量初始化（见下） |
| `BEGIN AFTERTRAIN` | `AfterTrain_Begin` | 强制调用 `@EVENTEND` |
| `BEGIN ABLUP` | `Ablup_Begin` | |
| `BEGIN TURNEND` | `Turnend_Begin` | 强制调用 `@EVENTTURNEND` |

EE 扩展另有 `FORCE_BEGIN`，跳过 `__CAN_BEGIN__` 检查（`Runtime/Script/Statements/Instraction.Child.cs:3056-3072`）。

## 各阶段内置处理顺序

### 标题（Title）

```text
// Process.SystemProc.cs:171-275（伪代码）
beginTitle():                                   // Title_Begin 状态
    清理 CALLTRAIN 残留 / 复位样式 / 清空备份状态    // :174-179
    装载有错误且未开 CompatiErrorLine → 报错并停留在标题   // :193-207
    if callFunction("SYSTEM_TITLE", force:false):
        state.SystemState = Normal              // 自定义标题，:208-211
        // @SYSTEM_TITLE 中必须 BEGIN 或 LoadGame/Quit，否则 Normal 跑空报错
    else: 打印标题/版本/作者 → [0] 从头开始 [1] 读取存档 → 等输入（Openning）  // :213-231
endOpenning():                                  // Openning 状态
    输入 0 → ResetData() + AddCharacterFromCsvNo(0) + 默认角色 → beginFirst()  // :244-253
    输入 1 → 有 @TITLE_LOADGAME 则调用；否则标准 LOADGAME 界面               // :255-264
    其他输入 → 重画选项重试                       // :266-273
beginFirst():                                   // First_Begin（标题选择 0 时直接调用）
    state.SystemState = Normal
    callFunction("EVENTFIRST", force:true, isEvent:true)   // :277-286
    // @EVENTFIRST 内不 BEGIN → Normal 跑空 → endNormal 抛 UnexpectedScriptEnd
```

新游戏的变量初始化由 `endOpenning` 中的 `vEvaluator.ResetData()` 完成（`Runtime/Script/Statements/Variable/VariableEvaluator.cs:1149-1166`）：重置全部变量默认值、清空角色列表（**全局变量**不重置，注释「グローバルは初期化しない方が都合がよい」），然后 `AddCharacterFromCsvNo(0)` 加入主人公，`GAMEBASE.CSV` 的 `DefaultCharacter` 存在时再加入。

因此「[0] 最初始开始」结束后，角色列表中**必定**已经有第 0 号角色（CSV 编号 0 的角色；`chara0*.csv` 不存在时按伪角色加入，见 `AddCharacterFromCsvNo` → `GetPseudoChara()` 回退）。脚本惯例的

```erb
;あなた登録
DELCHARA 0            ; 删掉开局就存在的那个 0 号角色
ADDCHARA 0            ; 再登记自己版本的主人公
```

删掉的就是它 —— 直接 `DELCHARA 0` 之所以不越界，前提正是这里的 `AddCharacterFromCsvNo(0)`（`AddCharacterFromCsvNo` 与 `ADDDEFCHARA` 走同一函数，语义一致）。

### 商店（Shop，主循环）

```text
// Process.SystemProc.cs:658-798（伪代码）
beginShop():                                    // Shop_Begin
    callFunction("EVENTSHOP", force:false, isEvent:true)  // 读档进入时无影响，
    // 注意：从 LOADGAME 直达时 state.calledWhenNormal=false，见 Begin() :278-284
endCallEventShop():
    if Config.AutoSave 且 calledWhenNormal: beginAutoSave()  // 自动存档
endAutoSave():
    callFunction("SHOW_SHOP", force:true)       // Shop_CallShowShop
endCallShowShop(): 等待输入 → Shop_WaitInput
shopWaitInput():
    0 ≤ 输入 < Config.MaxShopItem（默认 100，_replace.csv 可改）:
        ITEMSALES 非 0 且 BuyItem 成功（MONEY ≥ ITEMPRICE）
          → SELECTCOM 无关、BOUGHT=编号、ITEM+1、MONEY-价 → callFunction("EVENTBUY") → 回 SHOW_SHOP
        售罄 / 钱不够 → 临时行提示，重回 SHOW_SHOP
    其他输入 → RESULT = 输入 → callFunction("USERSHOP", force:true) → 回 SHOW_SHOP
```

`PRINT_SHOPITEM` 的显示范围是 `ITEMNAME`/`ITEMSALES`/`ITEMPRICE` 数组长度的最小者（`Runtime/Script/Process.ScriptProc.cs:222-224`）。购买判定与金额增减在 `VariableEvaluator.BuyItem`（`Runtime/Script/Statements/Variable/VariableEvaluator.cs:1721`）。**不执行 BEGIN 就永远留在 SHOP 流程**。

### 训练（Train）

`BEGIN TRAIN` 后的变量初始化（`beginTrain` → `vEvaluator.UpdateInBeginTrain()`，`Runtime/Script/Statements/Variable/VariableEvaluator.cs:1449-1489`）：

- `ASSIPLAY = 0`、`PREVCOM = -1`、`NEXTCOM = -1`；
- `TFLAG` 全 0、`TSTR` 全空串；
- 对**所有角色**（不只 TARGET）：`GOTJUEL`、`TEQUIP`、`EX`、`PALAM`、`SOURCE`、`TCVAR` 全 0；
- `STAIN` 按 `RESET_STAIN` 的默认值重置（`STAIN:2=2、STAIN:3=1、STAIN:4=8、其余 0`，`setDefaultStain`）；
- **NOWEX 不在此处重置**（1.728 起，改在 `@EVENTCOM` 直前的 `UpdateAfterInputCom`，`Runtime/Script/Statements/Variable/VariableEvaluator.cs:1524-1534`）；
- `PREVCOM` 由脚本负责更新，引擎不写。

离开 TRAIN 时这些值**不会**再初始化——若在 SHOP 里存档，这些值会带入存档；`NEXTCOM` 非负值的行为含 eramaker 遗留缺陷（`endCallEventTrain` 中 `NEXTCOM = 0` 而非 -1，`Runtime/Script/Process.SystemProc.cs:317` 注释），Emuera 仅为兼容保留，不推荐新代码使用。

指令选择的完整循环：

```text
// Process.SystemProc.cs:293-566（伪代码）
beginTrain():  UpdateInBeginTrain → callFunction("EVENTTRAIN", force:false)
               未定义则直接下一步
endCallEventTrain():
    NEXTCOM ≥ 0 → SELECTCOM = NEXTCOM → 直接进入 EVENTCOM（CALLTRAIN/DOTRAIN 路径）
    否则 callFunction("SHOW_STATUS", force:true)
endCallShowStatus():
    comAble[] 全部置 -1 → endCallComAbleXX()
endCallComAbleXX():  // 逐个编号调用
    foreach trainCode in 0..TrainName.Length-1（TrainName 来自 TrainName.csv/VariableSize.csv）:
        TRAINNAME 未定义 → 跳过
        @COM_ABLE{编号} 未定义 → 视为可用（Config.ComAbleDefault 控制）
        已定义 → 调用；RESULT != 0 → 可用，打印「指令名[序号]」，RESULT == 0 → 不显示
        // 此处记住可用性（comAble[]），运行时不会再次调用 COM_ABLE
    全部查完 → callFunction("SHOW_USERCOM", force:true)
endCallShowUsercom():
    vEvaluator.UpdateAfterShowUsercom()   // UP/DOWN/LOSEBASE/DOWNBASE/CUP/CDOWN 清零
    等待输入 → Train_WaitInput
trainWaitInput():
    输入对应 comAble 中已记录的可选指令 → SELECTCOM = 编号 → callEventCom()
    否则 → RESULT = 输入 → callFunction("USERCOM", force:true) → 回 SHOW_STATUS
callEventCom():
    UpdateAfterInputCom()   // 所有角色 NOWEX 清零
    callFunction("EVENTCOM", force:false) → endEventCom()
endEventCom():  state → Train_CallComXX → callFunction("COM{SELECTCOM}", force:true)
endCallComXX():
    RESULT == 0 → 指令中止，回 @EVENTCOMEND 路径（最终回 SHOW_STATUS）
    RESULT != 0 → callFunction("SOURCE_CHECK", force:true)
endCallSourceCheck():
    UpdateAfterSourceCheck()   // 所有角色 SOURCE 清零
    callFunction("EVENTCOMEND", force:false)
    // EVENTCOMEND 不存在、或其中没有 WAIT 系输入 → 引擎补一次 WAIT（NeedWaitToEventComEnd）
endCallEventComEnd(): 回 endCallEventTrain()（即回 SHOW_STATUS 重新画菜单）
```

要点：`@COM_ABLExx` 的判定结果在显示时记住一次，输入时只查表（`trainWaitInput` 用 `comAble[]`，`Runtime/Script/Process.SystemProc.cs:444-445`）；指令执行失败（`RETURN 0`）回到指令选择界面；`UPCHECK` 命令在执行时把 `UP`/`DOWN` 并入 TARGET 的 `PALAM` 并清零（`VariableEvaluator.UpdateInUpcheck`，`Runtime/Script/Statements/Variable/VariableEvaluator.cs:1552`）。

### 连续调教 CALLTRAIN / DOTRAIN

`CALLTRAIN n` 把 `SELECTCOM:1..n` 排成队列自动逐条执行（`SetCommnds`，`Runtime/Script/Process.cs:264-277`），跳过输入与显示（`skipPrint`）；队列耗尽时调用 `@CALLTRAINEND`（`endCallEventComEnd`，`Runtime/Script/Process.SystemProc.cs:543-553`）。`DOTRAIN` 只能在训练流程的特定状态使用（`doFlowControlFunction` 的 DOTRAIN 分支白名单，`Runtime/Script/Process.ScriptProc.cs:894-925`），否则报 `CanNotUseDotrainHere`。

### 升级（AblUp）、回合结束（TurnEnd）、结束训练（AfterTrain）

- **AblUp**（`Runtime/Script/Process.SystemProc.cs:580-644`）：`SHOW_JUEL` → `SHOW_ABLUP_SELECT` → 输入。0–99 一律先尝试 `@ABLUP{输入}`（即使未定义也不走 `@USERABLUP`，注释「そうしないと[99]反発刻印とかが出来ない」）；未定义则提示无效值重新输入。≥100 调用 `@USERABLUP`（`RESULT` = 输入值）。输入范围**不可**通过 `_replace.csv` 修改（1.705 起）。
- **TurnEnd**（`beginTurnend`，`Runtime/Script/Process.SystemProc.cs:646-656`）：强制调用 `@EVENTTURNEND` 后进入 `Normal`。若函数链跑空仍未 BEGIN，抛 `UnexpectedScriptEnd`——即文档所说「@EVENTTURNEND 里不 BEGIN 会报错」（实际是 `@EVENTTURNEND` 执行完后必须 BEGIN，否则报错）。
- **AfterTrain**（`beginAfterTrain`，`Runtime/Script/Process.SystemProc.cs:568-578`）：强制调用 `@EVENTEND`，之后进入 `Normal`。同理，`@EVENTEND` 结束前必须 BEGIN。

### 存档 / 读档

- **SAVEGAME / LOADGAME 命令**（`SAVELOADGAME_Instruction`，`Runtime/Script/Statements/Instraction.Child.cs:3074-3096`）：仅当 `SystemState` 带 `__CAN_SAVE__` 时可用，否则抛错；执行时先 `saveCurrentState` 备份当前 `ProcessState`（`Runtime/Script/Process.cs:937-948`）——取消（输入 100）时 `loadPrevState` 原地恢复，这正是「SAVEGAME/LOADGAME 像 CALL 一样返回」的实现；存档完成后 `endCallSaveInfo` 也调 `loadPrevState` 返回原处（`Runtime/Script/Process.SystemProc.cs:1033-1044`）。
- **写档**：`@SAVEINFO` 在实际写盘**之前**调用（`SaveGame_CallSaveInfo` → `endCallSaveInfo` → `vEvaluator.SaveTo`），供 `PUTFORM` 写入存档概要（`Runtime/Script/Process.ScriptProc.cs:289-298`）。
- **LOADDATA 命令 / LOADGAME 选号读档**：`LOADDATA` 执行时清空调用链并直接切到 `LoadData_DataLoaded`（`doFlowControlFunction`，`Runtime/Script/Process.ScriptProc.cs:810-828`）；读档把此前所有状态（包括函数调用栈）全部作废。
- **读档后**（`Runtime/Script/Process.SystemProc.cs:801-826`）：`LoadData_DataLoaded` → 有 `@SYSTEM_LOADEND` 则调用 → `LoadData_CallEventLoad` → 有 `@EVENTLOAD` 则调用（其间可 BEGIN）→ 都没有或执行完则 `endAutoSave` → `@SHOW_SHOP`（Eramaker 在此处直接进 `@SHOW_SHOP`，Emuera 插入两个系统函数）。
- 自动存档：`BEGIN SHOP` 从 Normal 进入且开 `Config.AutoSave` 时，先写 99 号存档（`AutoSaveIndex = 99`，`Runtime/Script/Process.SystemProc.cs:674-712`），有 `@SYSTEM_AUTOSAVE` 则用它完全替代默认行为。

## 与源码的差异/备注

1. ecd/ERB_Internal_Process 的函数表称 `@EVENTCOM` 的用途是「指令的具体效果」——不准确：`@EVENTCOM` 只是前置事件（可多重定义），指令本体是 `@COMxx`；`@EVENTEND` 标注为「游戏结束时」也不准确，实际是 `BEGIN AFTERTRAIN`（结束训练）时调用。
2. ecd/ERB_Internal_Process 说「`@CALLTRAINEND` 不是事件函数，不能多重定义」——与源码一致（`IsEventLabelName` 不含它）。
3. ecd/Flow 称标题流程「若 `@System_Title` 在 Return 之前没有调用 Begin 或 LoadData，则会报错退出」——源码层面是自定义标题结束后状态为 `Normal`，函数链跑空时 `endNormal` 抛 `UnexpectedScriptEnd`（`Runtime/Script/Process.SystemProc.cs:1105-1108`）；`LOADDATA`/`LOADGAME` 也可以代替 `BEGIN` 离开标题，文档已提到 LoadData，一致。
4. ecd/Flow 称 ABLUP 流程「如果输入 0~99 找到相应的 @AblUp……如果没有定义，就会再次等待用户输入」——源码在未定义时是先删一行、打印「无效值」临时行再重入输入循环（`ablupWaitInput`，`Runtime/Script/Process.SystemProc.cs:613-620`），语义一致但文档漏了提示行。
5. ecd/Flow 的 TRAIN 变量初始化列表与源码 `UpdateInBeginTrain` 一致，但漏了 `TSTR` 清空与 `TCVAR` 清零（源码 1.736f 起），并把 `SOURCE` 清零写入初始化列表（源码确实包含，1.728 起注释确认）；文档还说「为 STAIN:2 分配 2、STAIN:3 分配 1、STAIN:4 分配 8」——源码把这个默认值放进 `setDefaultStain`，可被 `RESET_STAIN` 命令改变，文档未说明。
6. ecd/Flow 称「如果在 @Source_Check 之后 @EventComEnd 不存在或其中没有给出 WAIT，那么在 @Show_Status 之前会执行一次 Wait」——与源码一致（`NeedWaitToEventComEnd`，`Runtime/Script/Process.SystemProc.cs:519-560`），但文档未说明该 WAIT 是在 `@EVENTCOMEND` 结束后、回 `@SHOW_STATUS` 前补上的。
7. ecd/Flow 称「在 Emuera 中如果 @System_LoadEnd 被定义则调用，否则如果定义了 @EventLoad 就执行 @EventLoad」——源码是两者按顺序都调用（不是二选一）：`beginDataLoaded` 调 `@SYSTEM_LOADEND`，`endSystemLoad` 再调 `@EVENTLOAD`（`Runtime/Script/Process.SystemProc.cs:801-819`）。
