# 表达式解析边界（C# 源码补充）

> 本页以仓库中的 `emuera.em/Emuera/` C# 参考实现为依据，补充 [表达式.md](表达式.md)、[运算符.md](运算符.md)、[变量.md](变量.md)。所有 `Runtime/…` 路径均相对该根目录。普通表达式、FORM 文本和语句级赋值使用不同入口，不能共用一套宽松语法。
>
> 本页记录源码实际行为，包括参考实现的缺陷；它不是通用 C# 语言语法说明。Qt/C++ 移植差异另见 [表达式移植核对](../../change/language/表达式移植核对.md)。示例中的 A、B 为整数变量，S 为字符串变量，多维数组须先声明。

## 解析入口与错误阶段

| 阶段 | 入口与职责 | 典型失败 |
| --- | --- | --- |
| 字符到词元 | `Parser/LexicalAnalyzer.cs:824-1030` 的 `Analyse` | 无法转换的数字、不闭合的引号/括号、非法字符、未完成的 rename |
| 词元到带类型项 | `Statements/Expression/ExpressionParser.cs:380-502` 的 `reduceTerm` | 连续值、缺操作数、错误终止符、类型不匹配、三元缺分隔符 |
| 变量与函数绑定 | `ExpressionParser.cs:239-318`，`Statements/Variable/VariableParser.cs:53-185` | 未定义名字、错误下标维数、函数参数不符合签名 |
| 装载期重构 | `Statements/Function/FunctionMethodTerm.cs:31-49`，`Statements/Variable/VariableTerm.cs:225-256` | 常量除零、常量重复次数非法、可检查的常量下标越界、无效常量关键字 |
| 运行期求值 | 各项 `GetIntValue` / `GetStrValue`，函数按自身实现取参数值 | 动态下标越界、空函数引用、动态除零、动态关键字不存在 |

`ReduceExpressionTerm` 可以返回 null，表示没有表达式；`ReduceIntegerTerm` 对空项直接报错，再检查结果必须为整数（`ExpressionParser.cs:143-171`）。空参数是否允许取决于调用者，不应统一替换为 0 或空串。

## 数字扫描与指数

源码：`Parser/LexicalAnalyzer.cs:138-270`。词法主入口把 ASCII `0` 到 `9` 识别为数值开头；普通表达式中的 `+` / `-` 首先是运算符。`ReadInt64` 本身还被转换函数直接调用，入口差异会影响带符号的进制前缀。

- 进制前缀必须在 `ReadInt64` 的当前字符处：`0x` / `0X`、`0b` / `0B`。前导零不表示八进制，`012` 为十进制 12。
- 尾数读完后识别 `p/P`（乘 2 的幂）或 `e/E`（乘 10 的幂）；**指数数字按尾数进制读取**，并由 long 不检查溢出地转换成 int。
- 十六进制的 `e/E` 本身是合法数字，优先被尾数吞入；`0x1e3` 是十六进制 `0x1E3`，即 483，而不是指数写法。`0x1p10` 的指数是十六进制 16，结果为 65536；`0b1p10` 的指数是二进制 2，结果为 4。
- 非零指数通过 double 和 `Math.Pow` 计算，再转换成 long，允许负指数并向零截断，如 `3e-1` 得 0。不能承诺全范围内精确的整数幂运算；指数为 0 时保留尾数，不经过 double。
- 没有尾数、只有指数标记、二进制中出现 2～9、数字转换溢出均有错误路径；不能把解析失败的数字默认为 0。double 的 NaN、Infinity 与超范围结果也被检查。
- 十六进制/二进制转换使用 `Convert.ToInt64` 的有符号位模式语义，如 `0xFFFFFFFFFFFFFFFF` 为 -1；十进制正字面量超过 long.MaxValue 会失败。因此普通表达式的 `-9223372036854775808` 会先解析超范围的正尾数，再处理负号，不能直接作为可用字面量。需要时可用 `(-9223372036854775807 - 1)`。

## 普通字符串、FORM 与原始文本

普通表达式的 `"…"` 是字面量，其中 `{A}`、`%S%`、`***` 都是文本。`@"…"` 才进入 FORM。普通字符串和 FORM 的反斜杠转义都支持 `\s`、`\S`、`\t`、`\n`；其他字符只保留反斜杠之后的字符，所以 `\%` 可在 FORM 中产生字面百分号。不存在 C# 的 `\uXXXX`、`\xNN` 自动解码规则；末尾孤立反斜杠有错误路径。

普通表达式不开放成对单引号字符串；专用 `AllowSingleQuotationStr` 模式与 `PRINTV` 的逗号终止文本模式必须分别处理（`LexicalAnalyzer.cs:930-951`）。`{A}` 不是普通表达式的括号形式，花括号插值仅在 FORM 中使用（`:992-994`）。`F[A]` 被解析入口明确拒绝（`ExpressionParser.cs:249-253`）；`名字.成员` 走未实现的命名空间分支（`:245-247`）。

## 变量下标的实际语法

源码：`ExpressionParser.cs:204-226,274-313,380-495`；`Statements/Variable/VariableParser.cs:53-185`。

冒号后的不带括号下标只读取一个项。遇到一个变量名时，不递归吞掉该变量后续的冒号；后续冒号属于外层变量。运算符不能直接成为该下标的开头。

| 写法 | 解释或结果 |
| --- | --- |
| `A:1 + 2` | `(A:1) + 2`，不是 `A:3` |
| `A:(1 + 2)` | `A:3` |
| `A:-1`、`A:++B` | 下标开头出现运算符，报错 |
| `A:(-1)`、`A:(++B)` | 语法可解析；负下标仍可能越界，自增仍有副作用 |
| `A:B:1` | A 的两个下标；B 按其省略规则读取 |
| `A:(B:1)` | A 的一个下标，值来自 B:1 |
| `A:`、`A::1` | 冒号后缺项，报错 |
| `LOCAL@函数名:1` | 先绑定关联局部变量，再解析下标；该功能只对允许关联名的变量有效 |

括号里的子表达式以普通表达式模式递归解析，故运算、函数调用、嵌套变量引用都可放入括号。最多读取三个显式下标；随后根据变量类别校验维数。

| 变量类别 | 完全省略 | 部分指定 |
| --- | --- | --- |
| 普通 0 维变量 | 无下标 | 有下标报错 |
| 普通 1 维数组 | 默认元素 0；RAND 有独立兼容检查 | 只能给一个下标 |
| 普通 2/3 维数组 | 生成 `VariableNoArgTerm`，可供需要数组本身的上下文使用 | 必须提供全部下标 |
| 角色标量（NAME 等） | 常规模式默认 TARGET | 一个下标为角色编号 |
| 角色 1 维数组（CFLAG 等） | 常规模式默认 TARGET 的元素 0 | 只给一个下标时，它是元素编号，角色仍为 TARGET；两个下标才是角色、元素 |
| 角色 2 维数组（CDFLAG 等） | 生成 `VariableNoArgTerm` | 必须同时提供角色编号及两个元素下标 |

`SystemNoTarget` 开启时，角色标量/1 维数组完全省略会保留无参数项，部分省略则报错。无参数项并不等于数组元素 0：直接求值、赋值、自增均抛“缺变量参数”（`VariableTerm.cs:406-440`）。

字符串下标由 `VariableStrArgTerm` 按变量及下标位置查询名表；空键、未定义键、没有适用名表都有错误路径（`VariableStrArgTerm.cs:34-70`）。裸名字先尝试变量/函数，之后才按当前变量的已定义关键字解释；有同名变量时不能强制把裸名字当关键字，应用字符串字面量。EE 的 ERD 用户名表也参与绑定，不是任意裸词都能作为关联键。

## 空实参与函数绑定

`ReduceArguments`（`ExpressionParser.cs:53-134`）保留内部空槽，但遇到结束括号/行尾直接结束：

| 输入 | 词元归约后的实参 |
| --- | --- |
| `F()` | 零个 |
| `F(1,)` | 一个，尾随逗号不产生最后的空槽 |
| `F(,1)` | null、1 |
| `F(1,,2)` | 1、null、2 |
| `F(,)` | 一个 null |

这些是解析结果，不表示 F 一定接受相应形式。内置方法的签名检查、默认参数逻辑以及用户函数的 `ConvertArg` 决定是否允许省略。函数定义模式把“形参、默认值项”成对保存，并对 `=` 两侧类型一致性进行检查；未写默认值时保存 `NullTerm` 标记，不能把它当作普通常量节点。

标识符后紧跟 `(` 时先进入函数调用分支；普通变量名不会因为同名而让 `A(1)` 成为数组访问。未加括号的函数名字可能生成函数引用项；它不是普通函数的无参调用。`UserDefinedRefMethodNoArgTerm` 的普通求值明确报错（`Statements/Function/UserDefinedMethodTerm.cs:126-153`），函数引用为空时有独立错误（`:89-108`）。

## 参数类型、宏与分析模式补充

内置方法的扩展参数检查涵盖省略、可变参数、SameAsFirst、REF、数组维数、CHARADATA、AllowConstRef 和 DisallowVoid（`Statements/Function/FunctionMethod.cs:121-291`），不能仅按返回的值类型判断参数是否合法。该文件 `_ArgType.Array3D`（:72）错误地检测 Array2D 标志，`ArrayDims`（:77-84）因而可能把仅标记三维的参数识别成 0 维；这是参考实现缺陷，需要与正常三维参数规范区分。

用户函数引用项重构时，引用参数调用 Restructure 但保留原对象，值参数接收重构后的替代项（`UserDefinedMethodTerm.cs:111-120`）。普通用户函数只重构参数，不因为参数全常量就执行函数体（:70-74）。有 HasUniqueRestructure 的内置方法走专用重构接口，不能套用普通“全部 SingleTerm 才折叠”规则（`FunctionMethodTerm.cs:33-38`）。

`AExpression` 基类默认整数访问器返回 0、字符串访问器返回空串；`NullTerm` 只保存类型而不保存构造参数，也不是 SingleTerm 常量（`Expression/AExpression.cs:16-29`、`Expression/Term.cs:6-17`）。这属于内部占位机制，不表示任意错误表达式可默认取零。`Program.AnalysisMode` 下，未找到的函数会计入临时表并返回 NullTerm(0)，普通执行模式则报错（`ExpressionParser.cs:255-268`）。

函数式宏实参扫描只维护圆括号深度，未对方括号/花括号单独计数（`LexicalAnalyzer.cs:1070-1123`）；逗号槽的空实参检查与普通函数调用不同。特别是末槽遇到右括号会直接跳转 exitfor，绕过 exitwhile 的空项检查，不能简单声称所有空宏实参都会被同一检查拒绝。宏替换与展开上限错误需单独验证。

ERD 字符串下标还存在实现不一致：`VariableStrArgTerm.GetIntValue` 查询字典时传变量名，Restructure 初次查询却传 null（:34-65）；缓存的字典可能影响后续查表。对用户名表应记录装载期/运行期差异，不应保证两条路径一定等价。动态变量的多维下标按顺序重算并写入 transporter，常量下标才复用固定索引（`VariableTerm.cs:47-69,154-161`）。

## FORM 插值的参数与终止符

源码：`Parser/LexicalAnalyzer.cs:1156-1300`；`Data/StrForm.cs:55-149,231-270`。

- `{}` 和 `%%` 是空插值，报错；`%…%` 第一项必须为字符串，`{…}` 第一项必须为整数，不能自动转换。
- 第二项是整数宽度，第三项必须是单个 LEFT 或 RIGHT 标识符，名字比较使用配置的比较规则；多余词元、第四参数和非法对齐名均报错。
- 宽度可以省略；`{A,,LEFT}` 会在解析第二项时因空整数表达式报错。单个尾随逗号如 `{A,}` 不产生宽度项；第三项省略（含 `{A,5,}`）默认 RIGHT。
- 宽度表示最小补齐宽度，超过宽度的内容不截断。`{…}` 把宽度转换成 int 后调用 PadLeft/PadRight，负值有 .NET 异常路径；`%…%` 会先做显示宽度修正，修正后小于文本长度则直接返回原串。不能把两种宽度错误行为合并。
- 百分号插值里，同层 `%` 被用作结束符，因此余数运算应放在括号中，如 `%TOSTR((5 % 2))%`。数字插值 `{5 % 2}` 则无此冲突。插值内函数调用的逗号不会结束函数的实参解析。
- FORM 根据调用入口选终止符。行尾模式中双引号、逗号、分号可属于原始文本；不能先对所有 FORM 执行普通表达式的“分号截断”。
- `\@条件 ? 真文本 # 假文本\@` 的两侧也是 FORM，且各自 trim 首尾空格/制表符；条件必须有整数表达式。缺 `?`、缺结尾 `\@` 是错误；有结尾但缺 `#` 为警告并补空假文本。
- 该字符串条件语法的分支扫描把 `\@` 当结束符，不能照普通表达式三元的括号规则推断任意嵌套。需要嵌套时用子 FORM 表达式或函数组织。
- 三连符号的禁用配置使其保留为文本，不表示未知语法错误；启用时相应角色变量的读取仍可能因 TARGET/MASTER/PLAYER/ASSI 无效而失败。

## 三元、连续单目与 CASE

普通三元可返回整数或字符串：`A ? "yes" # "no"` 本身合法，条件必须为整数且两分支同类型（`OperatorMethod.cs:178-189`）。分支无引号的原始文字只属于 FORM 条件形式。普通三元缺 `#` 或独立出现 `#` 都报错；同层连续三元左结合，真分支内嵌套需要括号。

连续前置运算符如 `!!A`、`-- -A` 不被 TermStack 接受，需逐层括号；同一项重复后置 `A++++` 也报错。`!A++` 因已处理前置而拒绝，`-A++`、`~A++` 则在延迟前置归约前先处理后置，不能概括成“一切前后置组合都禁止”（`ExpressionParser.cs:510-595`）。连续比较 `A < B < C` 有警告，仍按优先级对 1/0 继续计算，不能解释为数学区间条件（`:442-449`）。

CASE 使用专用解析入口（`ExpressionParser.cs:324-366`），普通表达式中的 TO/IS 均拒绝。`CASE x TO y` 两端必须同类型且不能再跟 TO。范围包含端点，不自动交换反向范围；字符串范围直接比较两端，不调用存在缺陷的字符串 <= 运算符。`CASE IS op x` 解析层检查的是二元运算符，并非只允许比较运算符，求值时计算“被选择值 op x”再判断非零；后续类型和控制流约束仍须满足。源码：`Statements/CaseExpression.cs:48-72`。

## 装载期检查与运行时短路

`FunctionMethodTerm.Restructure` 在普通重构分支中先遍历所有非 null 参数并递归重构，然后才决定是否折叠当前节点。它不根据 &&、||、!&、!| 或三元条件跳过未选分支的重构。

因此 `0 && (1 / 0)`、`1 ? 7 # (1 / 0)` 在进入装载期重构时，仍会先折叠内部常量除零并失败。非法类型/未定义名字也必须先通过解析，不能靠短路隐藏。运行期的动态项才按运算方法实现短路。

变量重构逐项折叠下标并检查可以静态确定的元素；角色编号维度、ARG/ARGS 以及引用变量有豁免路径。所有下标为常量只会固定索引，除非变量本身 `CanRestructure`，否则不会冻结变量值（`VariableTerm.cs:225-256`）。FORM 同样先重构各插值项，再把常量插值合并到相邻文本（`Data/StrForm.cs:171-201`）。

## 字符串赋值与数组右值

源码：`Statements/ArgumentBuilder.cs:999-1227`。

```erb
S = "a{A}b"        ; FORM 原始文本：双引号也保留，A 插值
S '= "a{A}b"       ; 普通字面量：结果为 a{A}b
S '= @"a{A}b"      ; FORM 表达式：结果插入 A 的值，无外层双引号
S += "x"           ; 右边必须为字符串表达式
S *= 2             ; 重复次数为整数表达式
A:0 = 1, 2, 3      ; 数值数组的连续元素赋值
S:0 '= "a", "b"    ; 字符串数组的连续元素赋值
```

左值必须是单个非 const 的变量项。整数 `=` 支持多个右值，复合赋值不支持多个；字符串 `'=` 支持多个字符串右值，`+=` 和 `*=` 只支持一个表达式。内部空项报错；尾随逗号的处理遵循前述 ReduceArguments 规则。字符串 `=` 右值是一个 FORM，不按逗号拆为数组元素。

字符串 `=` 入口跳过半角空格，并对最前/最后文本块 trim 空格和制表符；`SystemIgnoreStringSet` 的检查仅在该入口，不能描述成所有字符串赋值均被禁用。字符串 `-=`、`/=` 等被拒绝。数组具体连续写入与越界由变量 token 的 SetValue 实现承担，不是表达式内赋值。

以下各组应分别覆盖“成功值、语法拒绝、装载期失败、运行期失败”；本次补写以源码审计为依据，没有执行 C# 游戏实例。

| 下标/名表 | 冒号的归属、负下标括号、维数省略、SystemNoTarget、RAND 兼容、同名变量遮蔽关键字 |

| 函数/赋值 | 内部空槽与尾逗号、默认值、REF/REFMETHOD、`=` 与 `'=`、多值赋值与复合赋值拒绝 |
