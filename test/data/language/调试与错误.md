# 调试与错误

> 来源：ecd/docs/Debug_Mode.md、ecd/docs/Debug_Command.md、ecd/docs/Error_Index.md；zh 同名文件交叉核对（Error_Index 的 zh 版是空壳，见文末差异说明）。源码已实际核对：`UI/Game/EmueraConsole.cs`、`Runtime/Script/Process.ScriptProc.cs`、`Runtime/Script/Loader/ErbLoader.cs`、`Runtime/Script/Parser/LexicalAnalyzer.cs`、`Runtime/Utils/EmueraException.cs` 等。

## 概述

Emuera 提供两层调试设施：**调试模式**（以 `-Debug` 参数启动的完整调试环境：调试窗口、变量监视、调用栈、调试控制台、`DEBUGPRINT` 系指令、`;#;` 与 `[IF_DEBUG]` 条件行）和**调试命令**（在主控制台输入 `@...` 即时执行 ERB 代码的简易作弊口，无需调试模式，但需打开配置开关）。错误方面，引擎把异常分为脚本侧（`CodeEE`）与引擎侧（`ExeEE`）等类别，加载期问题以「警告等级 0～3」输出，运行期错误则打印位置与函数调用栈并写入 `emuera.log`。

## 调试模式

调试模式是 1.750 版新增的模式，与「使用调试命令」配置项无关。

### 启动与目录

- 命令行参数 `-Debug` 启动。实现上 `Program.Main` 解析 `debugModeOption` 并设置静态属性 `Program.DebugMode`（`Emuera/Program.cs:108、391`；旧的字符串比较 `-DEBUG` 分支已注释掉，`Program.cs:117-121`）。
- 启动时自动创建 `debug` 文件夹：变量监视列表与调试控制台日志都保存在其中（`Program.cs:210-220` 附近，`Directory.CreateDirectory(DebugDir)` + `ConfigData.Instance.LoadDebugConfig()`）。
- 若配置 `DebugShowWindow` 打开，启动即自动打开调试窗口（`UI/Game/EmueraConsole.cs:454-457`）。

### 条件行：`;#;`、`[IF_DEBUG]`、`[IF_NDEBUG]`

调试模式下，除正常执行的行之外：

- 以 `;#;` 开头的行会被当作代码执行；非调试模式下是普通注释。
- `[IF_DEBUG]～[ENDIF]` 之间的行仅调试模式执行；`[IF_NDEBUG]～[ENDIF]` 之间的行仅非调试模式执行（非调试模式下的 `[IF_DEBUG]` 块等同注释）。

```erb
;#;PRINTL 这一行只在调试模式下执行。
[IF_DEBUG]
  PRINTL 这一行只在调试模式下执行。
[ENDIF]
[IF_NDEBUG]
  PRINTL 这一行只有在非调试模式下才会执行。
[ENDIF]
```

实现伪代码：

```text
// Runtime/Script/Loader/ErbLoader.cs:214-233（预处理块状态机）
case "IF_DEBUG":
    ppMatch.Push("ELSEIF"); disabledStack.Push(Disabled); doneStack.Push(done);
    Disabled = !Program.DebugMode; done = !Disabled; break;
case "IF_NDEBUG":
    ...
    Disabled = Program.DebugMode; done = !Disabled; break;
// 之后 :378-380： if (ppstate.Disabled) continue;  被禁用的行整体跳过

// Runtime/Script/Parser/LexicalAnalyzer.cs:782-791（行首）与 :996-1001（行中）
case ';':
    if (st.CurrentEqualTo(";#;") && Program.DebugMode) { st.Jump(3); continue; }  // 当作代码
    else if (st.CurrentEqualTo(";!;") || st.CurrentEqualTo(";^;")) { st.Jump(3); continue; } // EE 专用注释行
    // 否则整行作为注释丢弃
```

即 `;#;` 的「执行」是词法层实现的：调试模式下跳过这三个字符继续按代码词法分析，因此既可用于整行也可出现在行中。注意 EE 还追加了 `;!;`（EE 中视为代码的注释行）与 `;^;`（`Runtime/Script/Parser/LexicalAnalyzer.cs:787-789`），官方文档未记载。

### 仅调试模式生效的指令

`DEBUGPRINT`、`DEBUGPRINTL`、`DEBUGPRINTFORM`、`DEBUGPRINTFORML` 输出到调试窗口（调试控制台），用法对应 `PRINT` 系；`DEBUGCLEAR` 清空调试窗口所有字符。`ASSERT` 在参数为 0 时抛错、非 0 时什么也不做。

这些指令带 `DEBUG_FUNC` 标志——「仅在 -Debug 启动时执行的命令」（`Runtime/Script/Statements/FunctionIdentifier.cs:22`；注册见 :377、259-262 相关）。非调试模式下它们无任何作用，且**不解析参数**（所以参数写错也不会报错）；但它们被视为「无用的指令」而非注释行，因此可以安全地紧跟在 `SIF` 之后。

```text
// Runtime/Script/Statements/Instraction.Child.cs:541-576
class DEBUGPRINT_Instruction : AInstruction {
    ctor(form, newline) { flag = METHOD_SAFE|EXTENDED|DEBUG_FUNC; if (newline) flag |= PRINT_NEWLINE; }
    DoInstruction(exm, func, state) {
        str = (func.Argument.IsConst) ? func.Argument.ConstStr : term.GetStrValue(exm);
        exm.Console.DebugPrint(str);            // EmueraConsole.cs:2056：非 DebugMode 直接 return
        if (func.Function.IsNewLine()) exm.Console.DebugNewLine();
    }
}
// ASSERT：Runtime/Script/Process.ScriptProc.cs:747-750
case FunctionCode.ASSERT:
    if (term.GetIntValue(exm) == 0) throw new CodeEE(trerror.AssertArgIs0.Text);
```

### 调试专用伪变量

`__FILE__`（当前文件名）、`__LINE__`（当前行号）、`__FUNCTION__`（当前函数名）只在调试模式下返回有意义值；非调试模式下返回 0 或空字符串。实现上按 `Program.DebugMode` 注册两套变量令牌（`Runtime/Script/Statements/Variable/VariableData.cs:333-341`；`Runtime/Script/Statements/Variable/VariableCode.cs:244-260`；`EmptyStrToken`/`EmptyIntToken` vs `Debug__FILE__Token` 等）。

### 调试窗口

- 打开方式：菜单「调试」、主控制台输入 `@DEBUG`（仅调试模式，否则报「调试窗口只能在 -Debug 启动时使用」）、快捷键 `Ctrl+D`。
- 三个标签页：
  - **变量监视**：在「目标」栏输入 `TALENT:MASTER:2` 等变量名或表达式即显示值；检索出错会显示错误详情；目标置空即删除。目标表在窗口关闭时保存、打开时载入，也可用「文件」菜单手动存取。目标可以是常量、表达式——但每次刷新都会实际调用表达式中的函数，若函数有副作用会反复触发。
  - **堆栈追踪**：当前函数在最上，依次是调用者。
  - **控制台**：调试输出目的地（`DEBUGPRINT` 系输出、主控制台的错误/警告副本）；底部文本框可输入调试命令，**不需要** `@` 前缀，且不受「使用调试命令」开关限制（见下节源码）。刷新可用 `Ctrl+R` 或 `DEBUGCLEAR` 清屏。
- 窗口大小可变，初始尺寸/位置可在设置对话框「调试」区修改。

## 调试命令

调试命令默认禁用：需在设置对话框勾选「启用调试命令」（`Config.UseDebugCommand`）后重启 Emuera。这是没有调试模式的旧版本提供的简易功能，建议用调试模式。

### 用法

脚本运行过程中（游戏进行时），在主控制台输入以 `@` 开头的文本即被识别为调试命令；格式与 ERB 相同，Emuera 立即执行。是否区分大小写取决于 `emuera.config` 的「忽略大小写」。

```erb
;调试模式下
@MONEY = 10000
@PRINTV FLAG:200
@PRINTFORM %NAME:MASTER%的CFLAG(1) = {CFLAG:MASTER:1}
@ADDCHARA 1

;直接输入变量或表达式也可输出其值（@ 后空格可省）
@ FLAG:200
@ @"%NAME:MASTER%的CFLAG(1) = {CFLAG:MASTER:1}"
```

专用命令（在主控制台 system 命令层处理，不经过 `Config.UseDebugCommand` 检查）：

- `@REBOOT`：重启并重新读取 emuera.config、csv、erb。
- `@OUTPUT`（`@OUTPUTLOG` 同）：把当前窗口日志输出到 `emuera.log`，已存在则覆盖。
- `@EXIT`（`@QUIT` 同）：退出 Emuera。
- `@CONFIG`：打开设置对话框。
- `@DEBUG`：打开调试窗口，仅 `-Debug` 启动时有效。

执行普通 ERB 指令时，`MASTER` 的 `NAME`/`CALLNAME` 会被强制改为「作弊者（イカサマ）」以防滥用——对应配置 `Config.ChangeMasterNameIfDebug`，执行后调 `vEvaluator.IamaMunchkin()`（`Runtime/Script/Process.ScriptProc.cs:92-99`）。

### 实现伪代码

```text
// UI/Game/EmueraConsole.cs:1479-1533（doSystemCommand，主控制台输入分发）
if (com == "REBOOT")  window.Reboot();
else if (com == "OUTPUT" || com == "OUTPUTLOG") OutputSystemLog("emuera.log");
else if (com == "QUIT" || com == "EXIT") window.Close();
else if (com == "CONFIG") window.ShowConfigDialog();
else if (com == "DEBUG") { if (!Program.DebugMode) PrintError(...); else OpenDebugDialog(); }
else { if (!Config.UseDebugCommand) { PrintError(CanNotUseDebugCommand); return; }
       DebugCommand(com, Config.ChangeMasterNameIfDebug, false); }        // :1528

// UI/Game/EmueraConsole.cs:2097-2187（DebugCommand）
DebugCommand(com, munchkin, outputDebugConsole) {
    runningERBfromMemory = true; GlobalStatic.Process.saveCurrentState(false);
    // 应用 _rename.csv 的 [[..]] 置换
    if (!com 以 '@'/'"'/'\\' 开头) line = LogicalLineParser.ParseLine(com, null);
    if (line 无效) {  // 当作表达式求值后转成输出指令
        term = ExpressionParser.ReduceExpressionTerm(...);
        com = (term 是整数) ? "PRINTVL " + com      // 调试控制台则 DEBUGPRINTFORML {..}
                            : "PRINTFORMSL " + com; // 同上 %..%
        line = LogicalLineParser.ParseLine(com, null);
    }
    func = (InstructionLine)line;
    if (func.Function.IsFlowContorol()) throw CodeEE("不能使用流程控制命令");   // IF/GOTO 等
    if (func.Function.IsWaitInput() || !func.Function.IsMethodSafe()
        || func.Function.IsPartial())   throw CodeEE("…命令不能使用");          // INPUT/WAIT、SIF 后继等
    switch (func.FunctionCode) { case PUTFORM: case UPCHECK: case CUPCHECK:
                                 case SAVEDATA: throw CodeEE("…命令不能使用"); }
    ArgumentParser.SetArgumentTo(func);
    process.DoDebugNormalFunction(func, munchkin);      // Process.ScriptProc.cs:92-99
    if (func.FunctionCode == SET && !outputDebugConsole) PrintSingleLine(com);
    catch (Exception e) { PrintError(e.Message) 或 DebugPrint(e.Message); process.clearMethodStack(); }
    finally { GlobalStatic.Process.loadPrevState(); runningERBfromMemory = false; state = temp_state; }
}
```

要点：调试命令在**临时保存/恢复执行状态**的环境中运行（不影响游戏进程的状态机），执行前做 rename 置换，禁止流程控制、等待输入、部分指令（`PUTFORM`/`UPCHECK`/`CUPCHECK`/`SAVEDATA` 显式列入黑名单）。调试窗口的变量监视也走同一条 `DebugCommand` 路径（`UI/Game/EmueraConsole.cs:1458-1460` 注释）。

## 错误与异常体系

### 异常类

定义在 `Runtime/Utils/EmueraException.cs`：

| 类 | 行号 | 含义 |
|---|---|---|
| `EmueraException` | :6 | 抽象基类，携带可选 `ScriptPosition`（文件名+行号，:99-113） |
| `ExeEE` | :25 | 引擎本体缺陷导致的错误（「emuera 本体的错误」） |
| `CodeEE` | :41 | 脚本侧原因的错误（绝大多数运行/解析错误都是它） |
| `IdentifierNotFoundCodeEE` | :57 | CodeEE 子类：未定义标识符相关 |
| `NotImplCodeEE` | :73 | 未实现功能（当前版本不可用） |
| `FileEE` | :89 | 存/读档中的错误 |

### 警告等级与加载期警告

加载/解析期的问题由 `ParserMediator.Warn(str, pos, level, ...)` 报告（`Runtime/Script/Data/ParserMediator.cs:82-152`）：`level` 为 0～3，低于配置 `DisplayWarningLevel` 的警告在非解析模式下不显示；`isError=true` 时按错误处理（读入失败的行执行时会报「执行了读入失败的行」）。警告同时进入调试控制台。

### 运行期错误输出

运行错误由 `Process` 统一捕获并输出（`Runtime/Script/Process.cs:486-550` 附近）：

```text
// Process.cs（节选，真实行号）
catch (EmueraException) 分支：
    console.PrintErrorButton("错误内容：" + 位置, position);   // :529-537 点击可打开编辑器定位
    console.PrintError("错误内容：" + exc.Message);
    console.PrintError("当前函数：@…（文件:行号）");           // :539
    console.PrintError("函数调用栈：");                        // :540-547 逐层打印
catch (Exception)：                                            // :496-501
    console.PrintError("在函数结束时发生了意料之外的错误: " + 类型 + 消息 + 调用栈);
```

`THROW` 指令即抛 `CodeEE(参数字符串)`（`Runtime/Script/Process.ScriptProc.cs:749-750`），错误信息为「THROW内容：…」。此外有无限循环检测：超过 `Config.InfiniteLoopAlertTime` 且无输入时弹窗询问是否强制结束（`Runtime/Script/Process.cs:368-401`）。

## 与源码的差异/备注

1. **`;#;` 的实现层级**：文档把它描述为「行」，源码实际在词法层处理（`Runtime/Script/Parser/LexicalAnalyzer.cs:782` 行首、`:996` 行中），因此行中出现 `;#;` 也有效——且严格说 `;#;` 之后接什么并不限于 PRINT。
2. **文档未记载的 EE 扩展**：`;!;`、`;^;` 注释行（EE 中视为代码，`Runtime/Script/Parser/LexicalAnalyzer.cs:787-789`）。`;!;` 在 ecd 兼容性矩阵中被标为「Emuera 扩展」，但语义（EE 专用代码行）只在源码注释中写明。
3. **错误索引的来源路径过时**：ecd/Error_Index.md 标注来源如 `Runtime/Script/Loader/ErbLoader.cs`、`Runtime/Script/Parser/LexicalAnalyzer.cs`、`UI/Game/HtmlManager.cs`，本仓库重构后对应 `Runtime/Script/Loader/ErbLoader.cs`、`Runtime/Script/Parser/LexicalAnalyzer.cs`、`UI/Game/HtmlManager.cs`；引用时需换算。索引自述「572 条」按旧工程统计，本仓库条目数可能略有出入（未逐条复核）。
4. **@EXIT 大小写与别名**：源码中 `EXIT` 与 `QUIT` 等价、`OUTPUT` 与 `OUTPUTLOG` 等价（`UI/Game/EmueraConsole.cs:1497-1509`），文档只列了其中之一。
5. **调试命令的黑名单细节**：文档只说「IF、CALL 等流程控制与 INPUT、WAIT 等输入指令不可用」；源码实际禁止的是 `IsFlowContorol()`、`IsWaitInput()`、非 `IsMethodSafe()`、`IsPartial()` 指令，外加显式黑名单 `PUTFORM`/`UPCHECK`/`CUPCHECK`/`SAVEDATA`（`UI/Game/EmueraConsole.cs:2145-2157`）——所以 `CALL` 这类普通指令其实可用，文档表述不精确。
6. **`MASTER` 改名行为**：文档说「强制改为『作弊者』」；源码由配置项 `Config.ChangeMasterNameIfDebug` 控制，并非无条件。调试窗口控制台则确实不改名（`munchkin=false` 路径或 window 侧调用）。
7. **两套文档差异**：zh/Debug_Mode.md 与 zh/Debug_Command.md 内容与 ecd 基本一致（同一翻译的不同抓取版本，ecd 版式更完整）；zh/Error_Index.md 是**空壳**——只有「运行错误/代码错误」两个空标题，没有表格与完整索引，必须以 ecd 为准。zh 无 Difference 之外的差异页需注意（Compatibility.md、Version_Index.md、Terminology.md 在 zh 目录不存在）。
