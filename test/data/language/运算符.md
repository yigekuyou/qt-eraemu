# 运算符

> 来源范围：本文的“本仓库”“当前实现”在描述语义、注册或源码行为时，指 C# 参考树 `emuera.em/Emuera/`；其他 C# 版本另按文中路径标注。资料收录范围仍指仓库内的参考材料。

> 来源：ecd/Operator.md（运算 exop）、ecd/Custom_Expression.md（自定义表达式内函数 UserMeth）；zh/Operator.md、zh/Custom_Expression.md 交叉核对。

## 概述

本页汇总 EraBasic（Emuera）全部运算符的语义、优先级与求值规则，以及可在表达式中调用的用户自定义函数（`#FUNCTION`/`#FUNCTIONS`）的约束。EraBasic 的运算符没有隐式类型转换——每个运算符只定义在 (long,long)、(string,string) 或 (string,int) 的特定组合上，其余组合在解析期报错。

## 运算符优先级（真实值）

```text
Emuera/Runtime/Script/Statements/Expression/OperatorCode.cs:5-50
  优先级 = 枚举值低 8 位（OperatorManager.GetPriority，OperatorCode.cs:118-121），数值越大越先归约：
    *  /  %            0x90
    +  -               0x80
    <  >  <= >=        0x65
    == !=              0x60    （不等号优先：比较运算分两级）
    << >>              0x70
    &  |  ^            0x50    （^ 与 & | 同级，优先级中立于逻辑与比较之间）
    && || ^^ !& !|     0x40
    # (三元分隔)        0x10
    ? (三元)            0x05    （低于其余一切二元运算符）
  标志位：__UNARY__（单目）、__UNARY_AFTER__（后置单目 ++/--）、__BINARY__、__TERNARY__
```

归约规则：`TermStack`（ExpressionParser.cs:510-686）在遇到新运算符时把栈顶"优先级 ≥ 新优先级"的运算全部先归约——同优先级左结合；`==`/`!=` 优先级低于 `<` 系，故 `A == B < C` 等价 `A == (B < C)`。三元 `?` 优先级最低，所以 `A && B ? C # D` 先算 `A && B`。

ecd/Operator.md 的"暂定优先级表"与源码基本一致，但该表把 `&` `|` 画进"逻辑运算符"分类、漏掉 `^`；zh/Operator.md 的同表还把"赋值复合运算"列写反过来看容易误解（`true`=允许复合赋值）。以本页源码表为准。

## 单目运算符

- `~`：按位取反（BitNot），仅整数。
- `!`：逻辑非，操作数为 0 得 1，否则得 0。
- `+`：单目正号，解析期直接返回原项（OperatorMethod.cs:94-95）。
- `-`：单目负号；对 `long.MinValue` 取负会打印系统行警告，结果仍是溢出值（OperatorMethod.cs:684-701）。
- `++` / `--`：自增/自减，有前置与后置两种形态；只作用于非 const 的变量（OperatorMethod.cs:85-91）。前置返回新值，后置返回旧值（OperatorMethod.cs:732-788）。可以用于普通表达式，例如 `A++ + 1`；C# 拒绝同一项连续叠加多个前后置单目运算符，需用括号明确组合。作为语句时是独立的一行。
- 单目运算符不适用于字符串。

## 算术运算符

- `+`：整数加法；字符串 + 字符串为连接。
- `-`：减法（仅整数）。
- `*`：乘法；字符串 × 整数为重复（见"字符串运算"）。
- `/`：整除。除数为 0 抛 CodeEE（OperatorMethod.cs:289-304）。
- `%`：取余。除数为 0 同样报错（OperatorMethod.cs:306-321）。

## 比较运算符

- 数值间：`==` `!=` `<` `>` `<=` `>=`，真为 1 假为 0。
- 字符串间：`==` `!=` `<` `>` `<=` `>=` 全部可用；比较从开头逐字符进行，出现不同字符即分出结果。实现用 `string.Compare(a, b, Config.Config.SCExpression)`，而 `SCExpression = StringComparison.Ordinal`（Runtime/Config/Config.cs:443），即**按 Unicode 码位序**比较，与区域设置无关。
- 数值与字符串比较：不允许，解析期报错。

```text
字符串比较（伪代码）
  OperatorMethod.cs:405-513
    c = string.Compare(左, 右, StringComparison.Ordinal)
    '>' : c > 0 -> 1
    '<' : c < 0 -> 1
    '>=': c < 0 -> 1   // ← 疑似 bug：条件与 '<' 相同
    '<=': c < 0 -> 1
```

> 注意：源码中 `GreaterEqualStrStr`（OperatorMethod.cs:475-481）的实现是 `if (c < 0) return 1L`，即字符串 `>=` 实际返回 `左 < 右` 的结果，与语义相反；`<=` 是正确的。这是实现层的 bug（文档语义正确）。

## 逻辑运算符与位运算符

### 逻辑（对整数做"非 0 即真"运算，结果为 1/0）

- `&&`：逻辑与（短路：左为 0 时不求右值，OperatorMethod.cs:525）
- `||`：逻辑或（短路：左非 0 时不求右值，OperatorMethod.cs:542）
- `^^`：逻辑异或（恰有一个非 0 时为 1；两侧都会求值）
- `!&`：逻辑与非（NAND；左为 0 时返回 1，不求右值）
- `!|`：逻辑或非（NOR；左非 0 时返回 0，不求右值）

C# `NandIntInt` 的条件使用 `||`，`NorIntInt` 使用 `&&`，因此两者也短路；不能仅凭名称或逻辑真值表推断求值顺序。

短路求值使得 `(ASSI >= 0) && (NO:ASSI == 1)` 在 `ASSI < 0` 时不会引用 `NO:ASSI`，从而避免越界错误；但求值顺序固定为先左后右，写成 `(NO:ASSI == 1) && (ASSI >= 0)` 时 `ASSI < 0` 会先在左项崩溃。

### 位（仅整数）

- `&` 按位与、`|` 按位或、`^` 按位异或（优先级与 `&` `|` 相同）。
- `<<` 左移、`>>` 右移：优先级高于比较与位运算、低于四则；移位数取右操作数的 int 截断（OperatorMethod.cs:642-668）。

## 字符串运算

- `+`：连接。
- `*`：字符串 × 整数重复；两侧均为字符串不允许。整数一方为负数报错，**≥ 10000 也报错**（OperatorMethod.cs:271-274，文档未提及上限）。
- 比较运算见上节。

```erb
STR:0 = % "あ" * 10 %
PRINTFORML STR:0 = "%STR:0%"   ; STR:0 = "ああああああああああ"
```

## 三元运算符

```erb
; 数值形式：可放进 () 中在普通计算里使用
A = X > 0 ? 1 # -1
; 字符串形式：整体包在 \@ ... \@ 中，可直接用于 PRINTFORM 系
PRINTFORM \@ X > 0 ? 成功 # 失败 \@
```

- `#` 是三元的分隔符（`:` 已被变量下标语法占用，OperatorCode.cs:45 注释）。
- 字符串形式的 `\@～\@` 不能省略 `#`（文档表述）；实现中缺失 `#` 是警告 + 假值视为空串（LexicalAnalyzer.cs:1287-1293）。
- 求值惰性：条件确定后只对选中的分支求值（OperatorMethod.cs:791-817、StrForm.cs:266-272）。
- 三元分支类型必须一致：`(long,long,long)` 或 `(long,string,string)`，其他组合报错（ReduceTernaryTerm，OperatorMethod.cs:178-189）。
- 连续三元左结合：`A ? B # C ? D # E` 等价于 `(A ? B # C) ? D # E`。
- then 分支中的嵌套必须加括号，例如 `A ? (B ? C # D) # E`；`A ? B ? C # D # E` 会因归约时项数不足而报错。

## 赋值运算符（仅语句级）

赋值在 EraBasic 中不是表达式：`=` 出现在普通表达式内部直接报错（ExpressionParser.cs:435-439），整行由 `LogicalLineParser` 识别为 `SET` 指令（LogicalLineParser.cs:558-588）。

- `=`：数值变量用 `AExpression` 右值赋值；字符串变量的 `=` 右值按 FORM 字符串解析（`LOCALS = "a{A}b"`），赋值前跳过半角空格（ArgumentBuilder.cs:1141-1170）。
- `'=`：用字符串**表达式**（而非 FORM 文本）给字符串变量赋值，可一次给数组多个元素：`STR:0 '= "a", "b", "c"`；数值变量用 `'=` 报错（ArgumentBuilder.cs:1143-1146、1146-1195）。
- 复合赋值：`+=` `-=` `*=` `/=` `%=` `<<=` `>>=` `&=` `|=` `^=`。词法层由 `ReadAssignmentOperator`（LexicalAnalyzer.cs:645-732）识别；语义等价 `变量 = 变量 op 右值`（`OperatorMethodManager.ReduceBinaryTerm(op, varTerm, src)`，ArgumentBuilder.cs:1186-1188）。`+=`/`-=` 且右值为常量时有加法快路径（ChangeValue）。数值变量才能用 `*= /=` 等；字符串变量只支持 `=` `'=` `+=` `*=`.
- `++` / `--`：整行开头的前置自增/自减是一条语句（`X++` 或 `++X` 形式由行首识别，LogicalLineParser.cs:388-413）；后面再跟任何内容报错。
- `==` 用在赋值语句位置不报错但会警告，并按 `=` 处理（eramaker 兼容，LogicalLineParser.cs:584-587）。

## 逻辑运算的短路求值（doc 专节要点）

- `&&`、`||`、`!&`、`!|` 都短路；`^^` 两侧都求值。
- 短路同样会跳过右项的式中函数调用，这是有副作用函数的第一个坑（见下）。

## 新增的运算（相对 Eramaker）

`==` `!=` `<` `>` `<=` `>=` 的字符串版本、字符串 `+` 连接、字符串 `*` 整数——均为 Emuera 扩展；Eramaker 时代这些组合不存在。

## 自定义表达式内函数（#FUNCTION / #FUNCTIONS）

以 `@～` 定义的函数若带 `#FUNCTION`（返回整数）或 `#FUNCTIONS`（返回字符串）标志，就可以在表达式中像内置函数一样调用：

```erb
X = GET_CFLAG(TARGET, Y)
STR = %GET_NAME(TARGET)%

@GET_CFLAG(ARG:0, ARG:1)
#FUNCTION
  SIF ARG:0 <= 0 || ARG:0 >= CHARANUM
    RETURNF 0
  RETURNF CFLAG:(ARG:0):(ARG:1)

@GET_NAME(ARG:0)
#FUNCTIONS
  SIF ARG:0 <= 0 || ARG:0 >= CHARANUM
    RETURNF ""
  RETURNF NAME:(ARG:0)
```

规则（与实现对应）：

- 必须以 `RETURNF` 结束，不能用普通 `RETURN`；`RETURNF` 的类型须与 `#FUNCTION(S)` 一致。省略 `RETURNF` 或执行到函数末尾时返回 `0` / `""`。
- 定义处参数可写 `()`（`@F(A, B)`）也可用逗号（`@F, A, B`），但在表达式中调用必须带 `()`；参数可带初始值（默认参数，类型检查见 ExpressionParser.cs:101-126）。
- 限制：
  - 不能被 `CALL` 调用；专用指令 `CALLF`/`CALLFORMF` 可以调用它们（用于无返回值场景）。
  - 函数体内不允许 `WAIT` 等输入命令与 `CALL` 等带函数调用的命令，违者报错。
  - 不支持重载：同名 `#FUNCTION(S)` 只有一个生效（第一个）。
  - 用户 `#FUNCTION` 会**覆盖同名内置式中函数**：名字解析先查用户标签（IdentifierDictionary.cs:596-607），查到 `IsMethod` 的用户函数即返回，不再落到内置表；未带 `#FUNCTION` 的普通函数则不会屏蔽内置函数（1.721 起的规则，IdentifierDictionary.cs:610-612）。覆盖内置函数时启动会警告，并可用配置禁止/静音。
- 副作用警告（文档专节，实现层面属实）：
  - 表达式内函数应只修改局部变量。短路求值可能使调用被整个跳过；
  - 表达式中变量与函数的求值顺序未定义（同一版本固定，跨版本可能变化），依赖它的代码不可移植；
  - 调试命令与变量监视窗口也会调用这些函数（监视更新频繁），有副作用的函数会因此出问题。

```text

    标识符后是 '(' -> 函数调用：
```

## EM 私家版扩展

本仓库（EM 私家版）在标准 Emuera 之上给表达式/词法层加的扩展点：

- HTML_PRINT 参数表达式支持 `px` 单位后缀：`TermEndWith.KeyWordPx`（ExpressionParser.cs:32-34），解析到 `px` 且后跟 `,` 或行尾时终止表达式（ExpressionParser.cs:417-422）；配套 `WordCollection.Next` 前瞻（WordCollection.cs:85-99）。
- 行内注释 `;!;`（以及 `;^;`，仅 EMEE）在词法分析中被跳过（LexicalAnalyzer.cs:787-793、1001-1005）。

## 与源码的差异/备注

1. **字符串 `>=` 的实现 bug**：`GreaterEqualStrStr` 用 `c < 0` 返回 1（OperatorMethod.cs:475-481），语义应为 `c >= 0`；文档描述（按"≥"含义）与实现不一致，实际行为等同 `<`。
2. `Runtime/Script/Statements/Expression/OperatorCode.cs:35` 的注释把 NOR 写成 `"!^"`，而词法与运算符表实际登记的是 `"!|"`（OperatorCode.cs:68、LexicalAnalyzer.cs:577-581）——仅注释笔误，行为与文档一致。
3. 字符串 `*` 整数有"重复次数 ≥ 10000 报错、负数报错"的限制（OperatorMethod.cs:271-274），两套文档均未记载。
4. `\@…?…\@` 缺 `#` 是"警告 + 假值为空串"而非错误（LexicalAnalyzer.cs:1287-1293）。
5. 复合赋值运算符全集比 ecd/Operator.md 与 ERB_Expressions.md 列出的（`+= -= *= /= %= '`=`）更宽：还包括 `<<= >>= &= |= ^=`（LexicalAnalyzer.cs:691-726）。
6. `++`/`--` 文档说"用于代替赋值语句，不能与其他运算符组合使用"：实现上前置/后置形态在普通表达式中同样可解析（`__UNARY__|__UNARY_AFTER__`），但仅限变量操作数；"不能组合"只是使用约定而非解析期限制。
7. 字符串比较使用 `StringComparison.Ordinal`（Config.cs:443），不区分大小写与否不受区域设置影响；文档未指明比较规则，实际是码位序。
8. zh/Operator.md 正文与 ecd/Operator.md 等价（措辞略异，如"あ"被译作"啊"）；zh/Custom_Expression.md 与 ecd/Custom_Expression.md 内容一致。
