# 移植差异 · 语句与复合语句

> 对应 `test/data/language/语句与复合语句.md`（该文档只保留 C# 语义）。规则见 [`../README.md`](../README.md)。

## 命令语句：本移植的三阶段映射

`test/data` 的表格只保留 C# 一列；本移植（`src/eraengine`）的对应为：

| 阶段 | C# 原版 | 本移植 |
| --- | --- | --- |
| ① 指令解析 | `LogicalLineParser.ParseLine`（`LogicalLineParser.cs:386`）→ `InstructionLine`（`:428`/`:438`）→ `ArgumentBuilder.CreateArgument`（`Instruction.cs:21`、`ArgumentParser.cs:32`）→ `Argument`（`Argument.cs:11/19`） | `AstBuilder::build`（`ast/ast_builder.cpp:585`）：词法 → 行首词大写为 `functionName` → `classifyInstructionKind`（`ast/argument_parser.h:174`，**单一来源 = 指令规范表 `kInstructionSpecs`**）得 `ArgKind` → `ArgumentParser::build` 归约实参 |
| ② 行结构 | `InstructionLine` 是指针树/双向链表：`NextLine`/`JumpTo` 由第三轮 `SetJumpTo` 回填（`Instruction.cs:17`） | **拍平**：`LogicalLine`（`ast/logical_line.h:240`）值类型数组 + **行号索引**（`lineIndex`/`nextLine`/`jumpTo`/`ownerFunction`），控制流由 `ScriptRunner` 与 `EraParseTable::jumpTo[]` 驱动 |
| ③ 计算 | `Process.ScriptProc.cs:55`/`:93` → `DoInstruction`（`Instruction.cs:18`） | `ExecutionEngine::executeInstruction`（`GameProc/execution_engine.cpp:712`）按 `functionName` 分派；实参走 `Operand::ast` → `ExpressionEvaluator::evaluate`（`:501`/`:506`），无 `ast` 时回落 `raw`（整段字面量）。控制流（IF/SIF/REPEAT/FOR/WHILE/GOTO/CALL…）不在这一层 |

实参结构：`Operand{raw, isString, isVariable, ast}`（`ast/logical_line.h:82`，`ast` 即归约后的
`ExpressionNode`）+ `TypedArgument{kind, operands, params, exprs, minArgs/maxArgs, typeOk}`（`:226`）。

**取舍**：拍平的收益是无指针追链、拷贝/序列化友好（按行号直接定位）；
代价是结构嵌套不再显式可见，须靠测试守不变量
（`21_GOTO_LABEL_SCOPE`、`29_DOC_EVENT`、`33_END_VARIABLE`）。
同一收敛也体现在实参上：C# 的 40 个 `Argument` 子类 → 本移植 `ArgKind` 枚举
（`ast/logical_line.h:106`），类型/个数校验失败由 `TypedArgument::typeOk/typeError`
转成装载期诊断（code = `arg-check`，见 [`../language/调试与错误.md`](调试与错误.md)）。

另外两条与 C# 的对应：

- 参数格式：C# `FunctionArgType` → 本移植收敛为 `ArgKind` + 归约后的表达式。
- 「以内置函数名开头的整行」：C# 归 `LogicalLineType.Function`；本移植标
  `LogicalLine::isFunctionCall`，返回值写 `RESULT`/`RESULTS:0`（`ast/ast_builder.cpp:778`）。

## 指令规范表的映射陷阱（2026-10 补表时实证，两条都会踩坏功能）

1. **多参指令不能用 `IntExpression`** —— 本引擎的 `IntExpression` 是「整行归约为一个表达式」
   （对齐 C# `ReduceArguments` 取剩余全部词），`TOOLTIP_SETCOLOR 0, 0` / `ADDCHARA 3, 5`
   若用它会被并成**单个**操作数（个数=1、求值失败）；必须用 `Expressions`（逗号族逐参归约）。
   另：C# 的 `SP_SWAP`（`<数値>,<数値>`）与本引擎的 `ArgKind::Swap`（**变量**交换，首参必须是
   变量）同名不同义，不可直映。
2. **同时是内置函数的名字不得入规范表**（`PUTFORM`/`STRLEN*`/`COPYCHARA`/`PICKUPCHARA`/`GETTIME`
   …共 15 条）—— 这些行由 `AstBuilder` 转成函数语句（`isFunctionCall`，`arguments` 恰有 1 个调用
   操作数），按 `VOID` 等规范校验会恒报「参数过多」。判定以 `isBuiltinFunction` 为界，
   已在 `src/eraengine/test/test_argument_types.cpp` 用 static_assert 固定。

顺带收益：此前这些名字回落 `Raw` 时按空白+逗号切分，`ASSERT 1 == 1` 会被切成
`1`/`==`/`1` 三段、`==` 无法归约 → 刷 `expr-parse` 误报；按 `IntExpression` 整行归约后
example 的 `expr-parse` 由 28 降到 25。
