# 资源、配置与存档加载阶段迁移（2026-10-10）

参考语义保留在 test/data；本文件记录 C++ 移植实现。已阅读 test/data/README.md、LOADDATA/LOADGLOBAL/DELDATA 的参考语义，追踪 EraEngine 装载、ConfigLoader、ResourceImageProvider、ExecutionEngine 和系统存读档画面回调。

## 实现

- ResourceImageProvider::setRoot/reloadAtlas 在装载边界递归读取 resources CSV，建立 Sprite 元数据。hasResource/intrinsicSize/spriteOffset/loadResourceImage/requestImage 不再触发图集结构解析。像素和裁切继续惰性缓存；reloadAtlas 同时清除两层像素缓存。空目录清空资源；同目录 setRoot 也重新读取。EraEngine::loadFinishedHook 确保同步与异步 reload 均刷新资源。
- ConfigLoader 装载、merge、clear、设置修改和单项保存更新时预计算 GETCONFIG 白名单输出、整数、布尔和颜色缓存。getBool/getInt/configValueInErb 只读这些缓存。EraEngine 的颜色与 FORM 配置回调不再拆字符串。配置文件仍按既有加载顺序与 fixed 优先级选值；显式修改设置立即重建已加载视图。
- VariableStorage::decodeSaveData 解码成 SaveSnapshot（角色清单、带枚举的 SaveCell、名称、整型下标、qint64/QString 值、描述）；applySaveSnapshot 只应用结构化内容。无效头、未知 tag、非法整数、负下标或缺失角色清单在应用前拒绝，不修改运行状态。restoreSaveData 保留为兼容显式文本导入入口，执行器不调用它。
- ExecutionEngine::reloadSaveSnapshots 在目录设置和游戏装载完成时读取普通存档和全局文件。LOADDATA 和系统 LOADGAME 共用 loadSaveSnapshot；命令/函数 CHKDATA 和系统画面读取相同可用性缓存。SAVEGAME/SAVEDATA 共用 writeSaveSnapshot，成功提交后立即更新对应缓存；DELDATA 成功删除后清缓存，删除失败报错。关闭游戏清目录、配置和存档缓存；新游戏变量重置保留磁盘快照。
- LOADGLOBAL 应用 GlobalSnapshot 中已解码的整型/字符串单元与唯一码。SAVEGLOBAL 成功提交后刷新全局快照。新写 JSON 整数用十进制字符串保留 qint64 精度，兼容旧数字 JSON。普通和全局保存采用 QSaveFile，检查完整写入及 commit；失败不覆盖已加载快照。
- 修复 dumpSaveData 的 DedicatedVar 表为每实例局部变量；原 static 表会持续引用第一次序列化的 VariableStorage 成员。

## 外部变化与刷新边界

运行读取使用装载快照。外部新增、替换、删除资源 CSV 或存档不会在查询中偷偷解析；调用 ResourceImageProvider::reloadAtlas、EraEngine::reloadSavedData（Q_INVOKABLE）或完整游戏 reload 显式刷新。完整 reload 重读配置。设置修改入口立即更新内存配置。单独图像文件解码仍可惰性发生，刷新图集清除已有像素缓存。未增加文件监视器或自动轮询。

## 已知限制

- 现有移植版 eraemu-save-v1 和 save_global.dat JSON 格式延续；不能读取 C# 二进制存档。普通存档仍只覆盖既有 dumpSaveData 支持的 1D/2D 全局、角色与系统单元，不新增原本遗漏的 3D/特殊角色标记序列化。
- 普通行式字符串可以包含制表符，换行尚无转义协议，含换行的普通字符串会被解码拒绝并使保存失败；全局 JSON 支持换行。SAVETEXT 禁止换行。
- 普通存档校验仍没有 GameBase 代码/版本元数据；全局唯一码沿用原有标题/版本哈希。LOADDATA 保留既有执行流程，没有补齐 C# SYSTEM_LOADEND/EVENTLOAD 转移。LOADGLOBAL 延续对已记录单元逐个覆盖语义，未新增 C# 扩展全局变量默认值重置。
- getConfig 仍返回已加载原始文本，调用者自行进行字符串枚举选择；GETCONFIG 输出为预转换文本，表达式结果装箱时仍按返回类型转数值。配置结构和 RGB/布尔解析不在运行回调发生。
- Android SAF 的 provider 枚举、opaque document ID、写授权和 QSaveFile 支持未在真实 Android 设备验证；旧 review-feedback.txt 的 SAF 问题属于另一任务，没有在这次改动中宣称解决。
- 所有快照驻内存，未设置大型存档总量上限。现有资源 provider 静态缓存仍遵循既有线程使用方式，未新增跨线程锁。

## 本轮补齐：变量、角色与强类型配置

- `VariableStorage::captureSaveSnapshot` 直接遍历强类型存储，写盘由同一快照序列化；普通存档、SAVEGLOBAL 成功后直接安装捕获快照，不通过序列化结果反向解码。全局整数和 SAVEVAR 整数使用十进制字符串，读取兼容旧 JSON number，同时避免新的 `double` 转换。
- `ExecutionEngine` 在目录装载时递归扫描 `sav` 下变量档，解码为完整 `VariableSnapshot`；LOADVAR 只应用缓存。SAVEVAR 使用动态相对文件名并在 QSaveFile 成功提交后更新对应快照；目录切换会清理并重新扫描缓存。坏档解析先完成临时快照，拒绝时不写入运行状态。
- `ExpressionEvaluator` 在 `setSaveDirectory` 时预解码角色档。LOADCHARA 只追加已解码角色条目；SAVECHARA 先捕获选定条目，写入成功后更新缓存。表达式和命令路径使用同一缓存，显式 reload 可看见外部替换/删除，目录切换会清空旧目录角色档缓存。
- ConfigLoader 增加预计算的 typed integer provider；EraEngine 注入 GETCONFIG。GETCONFIGS 保留字符串 provider 兼容，旧的字符串 provider 在未提供 typed provider 时仍可工作；颜色和清空配置后的缓存均覆盖测试。

## 旧普通存档的私有变量兼容

旧版 `eraemu-save-v1` 写入器曾将包含 U+001F 分隔符的函数私有键写入普通存档。解码现在仍完整校验 tag、字段、下标和整数值，但跳过这些私有记录，继续解码前后的公开记录；有效旧档不会因私有键被整体拒绝。新写存档继续排除私有键，不改变存档格式。

`applySaveSnapshot` 保留当前函数私有值及 LOCAL/LOCALS、ARG/ARGS、别名和 REF 上下文，也防御性跳过调用者直接传入的私有单元。损坏的公开或私有记录仍使解码整体失败，输出快照和运行状态保持不变。

`test_load_snapshots` 回归覆盖八种记录类型及旧 SI/SS 标量形式、混合公开/私有记录后的公开值恢复、私有值及调用上下文保护，以及格式损坏的原子拒绝。测试可选传入一个真实旧档路径进行只读解码验证；默认运行使用临时目录和内存构造档案，不依赖游戏数据。
