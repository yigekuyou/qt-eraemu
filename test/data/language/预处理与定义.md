# 预处理与定义

> 来源范围：本文的“本仓库”“当前实现”在描述语义、注册或源码行为时，指 C# 参考树 `emuera.em/Emuera/`；其他 C# 版本另按文中路径标注。资料收录范围仍指仓库内的参考材料。

> 来源：ecd/docs/Function_and_Preprocessor（函数与预处理指令）、ecd/docs/Header_File（头文件 ERH）、ecd/docs/ERB_File_Format（Eramaker 的 ERB 文件格式）；Era-Chinese-Documentation/docs 同名三篇交叉核对；源码 `Runtime/Script/Loader/ErbLoader.cs`、`Runtime/Script/Loader/ErhLoader.cs`、`Runtime/Script/Parser/LogicalLineParser.cs`、`Runtime/Script/Parser/LexicalAnalyzer.cs`、`Runtime/Utils/EraStreamReader.cs`、`Runtime/Script/Data/DefineMacro.cs`、`Runtime/Script/Data/LabelDictionary.cs`、`Runtime/Script/Data/UserDefinedVariable.cs`。

## 概述

EraBasic 脚本在真正执行前要经过两道「装载期」处理：先是**预处理**（注释剥离、`[[～]]` 全置换、行连接、`[SKIPSTART]` 等区块行的裁剪），再是**定义**（`@` 函数声明、`#` 开头的属性/定义指令、ERH 头文件中的 `#DIM`/`#DEFINE`）。这一层决定了哪些代码进入运行时、函数带什么参数、变量如何声明、宏如何替换。装载入口是 `ErbLoader`（ERB）与 `ErhLoader`（ERH），逐行读入由 `EraStreamReader` 完成，词法与宏展开由 `LexicalAnalyzer` 完成。

## 装载顺序与文件类型

- 处理顺序：`csv/` 内文件 → `*.ERH` → `*.ERB`（文档；对应源码中先 `ErhLoader.LoadHeaderFiles` 再 `ErbLoader.LoadErbDir`）。因此 ERH 中的 `#DIM`/`#DEFINE` 不会作用于 CSV 内容；而 `_rename.csv` 的 `[[～]]` 置换反过来会适用于 ERH（EraStreamReader 构造时 ERB/ERH 均传 `useRename:true`）。
- Emuera 读取 `ERB` 文件夹下所有 `*.ERB`、`*.ERH`；ERD 资源文件见 language/资源相关主题。
- EE 扩展：名字中含 `#` 的子目录里的 ERB 会**先**于其他 ERB 装载（`ErbLoader.LoadErbDir` 中的「ファイル読み込み順拡張」）。

```text
// ErbLoader.cs:44-138（伪代码）
LoadErbDir(erbDir):
    firstDir = 所有名字含 '#' 的子目录          // :51
    foreach f in firstDir 的 *.ERB: loadErb(f)  // :62-81  先装
    foreach f in erbDir 的 *.ERB:  loadErb(f)   // :84-98  后装
    setLabelsArg()      // 解析所有函数的参数声明      // :105
    ParseScript()       // 三轮解析（见下）           // :114
```

## ERB 文件的基本行规则（装载期）

### 注释与空行

- 行首（第一个非空白字符）为半角 `;` 的行是注释行，整行忽略；空行也忽略。
- Eramaker 篇文档称「不支持行尾注释」。**Emuera 自 1.807 起支持行中注释**：`LexicalAnalyzer.Analyse` 在词法分析中遇到 `;` 即把光标跳到行末（`Runtime/Script/Parser/LexicalAnalyzer.cs:995-1003`），所以 `A = 1 ; 注释` 在 Emuera 中合法、在 Eramaker 中非法。
- 三种特殊注释前缀（`LexicalAnalyzer.SkipWhiteSpace`，`Runtime/Script/Parser/LexicalAnalyzer.cs:765-798`）：
  - `;!;`（及 `;^;`）：被当作空白跳过，其后语句**由 Emuera 执行**；Eramaker 把整行当注释。用于「只希望 Emuera 执行」的代码。
  - `;#;`：仅调试模式下被跳过（其后语句执行）；非调试模式下按普通注释处理。即「只在调试模式执行」的行。
  - 其余 `;`：注释，忽略至行末。

### 半角输入与字符串

- 数字、指令、变量名、函数名用半角字符；`PRINT` 的正文若用 `""` 包住会被原样打出引号（Eramaker 篇规则；Emuera 中字符串字面量仅在表达式内合法）。

### 一行的完结与行连接

- Eramaker：一条指令不可拆成多行。
- Emuera EE 扩展支持行连接：以单独一行 `{` 开始、单独一行 `}` 结束，中间的若干物理行被拼接为一个逻辑行（`EraStreamReader.ReadEnabledLine`，`Runtime/Utils/EraStreamReader.cs:124-180`）。拼接时以 `ReplaceContinuationBR` 连接（FORM 内换行语义）；`{`/`}` 行上混入其他字符、或未闭合就到文件尾都会抛错（`NotCloseLineContinuation` 等）。

### [[～]] 全置换

- 装载时 `EraStreamReader` 用正则 `\[\[.*?\]\]` 匹配并对 `_rename.csv` 中登记的键做整词替换（`Runtime/Utils/EraStreamReader.cs:82-115`），ERB 与 ERH 都适用；无法匹配的 `[[～]]` 交给词法分析器报错。

## 预处理区块行 [XXX]

`[` 开头（且下一个字符不是 `[`，避免与 `[[` 置换混淆）的行在 `ErbLoader.loadErb` 中被识别为预处理指令（`Runtime/Script/Loader/ErbLoader.cs:364-377`）：读入 token 与 token2，交给 `PPState.AddKeyWord`。**同一行其后不得再写任何内容**，否则警告 `IgnoreAfterPreprosessor`。

可用的指令（`PPState.AddKeyWord`，`Runtime/Script/Loader/ErbLoader.cs:191-334`）：

| 区块 | 作用 |
| --- | --- |
| `[SKIPSTART]`～`[SKIPEND]` | 之间各行 Emuera 完全不读入。用于书写只给 Eramaker 执行的代码（配合 `;!;` 可双向分版本）。 |
| `[IF XXX]`～`[ELSEIF XXX]`～`[ELSE]`～`[ENDIF]` | 按宏 `XXX` 是否已 `#DEFINE` 裁剪多行。`[IF]` 判定即 `GetMacro(XXX) == null`（`Runtime/Script/Loader/ErbLoader.cs:247`）。 |
| `[IF_DEBUG]`～`[ENDIF]` | 仅调试模式保留，非调试模式视同注释。 |
| `[IF_NDEBUG]`～`[ENDIF]` | 与 `[IF_DEBUG]` 相反，仅非调试模式保留。 |

规则与错误行为：

- `[SKIPSTART]` 嵌套、`[SKIPEND]`/`[ENDIF]` 无配对、`[ELSEIF]`/`[ELSE]` 出现在非条件块中等都会产生警告；区块可以嵌套，内部用 `disabledStack`/`doneStack`/`ppMatch` 三个栈维护（`Runtime/Script/Loader/ErbLoader.cs:187-334`）。
- `[ELSEIF]` 遵循「一旦某分支成立，后续分支全部禁用」的短路语义（`Disabled = done || ...`，`:262`）。
- 文件结束时若仍有未闭合区块，警告缺少对应的 `[SKIPEND]`/`[ENDIF]`（`PPState.FileEnd`，`:324-333`）。
- Eramaker 不认识这些行，需要兼容时用 `;!;` 前缀（见上节）。

```text
// ErbLoader.cs:191-334（伪代码）
AddKeyWord(token, token2):
    case "SKIPSTART": skip=true; Disabled=true; push 状态栈
    case "IF_DEBUG":  Disabled = !DebugMode
    case "IF_NDEBUG": Disabled =  DebugMode
    case "IF":        Disabled = (GetMacro(token2) == null)
    case "ELSEIF":    Disabled = done || (GetMacro(token2)==null); done |= !Disabled
    case "ELSE":      Disabled = done; done = true
    case "SKIPEND"/"ENDIF": 弹栈恢复
    若 skip 则 Disabled = true   // SKIP 内嵌套 IF 全部无视
```

## 函数声明行 @ 与跳转标签 $

### @ 函数

- `@函数名`（可跟参数列表）声明一个函数，生成 `FunctionLabelLine`（`LogicalLineParser.ParseLabelLine`，`Runtime/Script/Parser/LogicalLineParser.cs:285-380`）。
- 函数名属于事件函数名（`EVENTFIRST`/`EVENTTRAIN`/`EVENTSHOP`/`EVENTBUY`/`EVENTCOM`/`EVENTTURNEND`/`EVENTCOMEND`/`EVENTEND`/`EVENTLOAD` 等，`Runtime/Script/Data/IdentifierDictionary.cs:54-69`）时标记 `IsEvent=IsSystem=true, Depth=0`；系统函数名（`SYSTEM_TITLE` 等）标记 `IsSystem=true, Depth=0`。
- 非事件函数重名：依配置 `WarnNormalFunctionOverloading` 警告「函数已被定义」（`Runtime/Script/Loader/ErbLoader.cs:413-422`）。
- `$标签` 生成 `GotoLabelLine`，归属其上方最近的函数；同一函数内 `$` 标签重名警告（`Runtime/Script/Loader/ErbLoader.cs:433-441`）。
- 任何语句出现在函数声明行之前都会警告 `LineBeforeFunc`（`Runtime/Script/Loader/ErbLoader.cs:461-462`）。

### 函数参数声明

参数写在 `@` 行上，两种写法等价：`@FUNC, ARG:0, ARGS:0 = "xx"`（逗号式）与 `@FUNC(ARG:0, ARGS:0 = "xx")`（括号式）；还支持 `@FUNC[子名]` 形式的子名（源码保留但标注 TODO「結局実装しないかも」）。解析在全部文件装载完后的 `setLabelsArg → parseLabel` 中统一进行：

```text
// ErbLoader.cs:541-676（伪代码）
parseLabel(label):
    若 label 是事件函数:
        带参数 → 警告 EventFuncHasArg；ArgLength = -1（调用方给多少 ARG 都行）
    否则:
        逐个参数 (i*2 项为变量项, i*2+1 项为初始值):
            变量项必须可赋值（VariableTerm 且非常量）
            非引用型参数必须带常量下标（如 ARG:0）
            重复参数 → 警告
            由 maxArg/maxArgs 统计 ARG/ARGS 实际使用上限
            初始值:
                省略 → ARG/ARGS/私有变量型给 0 或 ""（:636-645）
                显式给出 → 必须是常量（SingleTerm）、类型一致；
                          且只有 ARG/ARGS/函数私有变量（IsPrivate）可以给初始值
                          引用型(REF)参数不能给初始值（:653-654）
```

文档要点与之一致（ver1.808 起类型不符直接报错、字符串字面量要 `""`、格式化字符串用 `@"～"`；`CALL`/`JUMP`/`CALLFORM`/`TRYCALL` 系均可带参）。参数是**值传递**；用 `#DIM REF` 声明的引用型形参可实现引用传递（ver1.810+）。非 `ARG`/`ARGS`/私有变量（如 `A`、`STR`）也可作形参，但 ver1.808 起不能设初始值、不能省略。变量表达式作下标（`ARG:(X+1)`）要求下标整体为常量。

## # 开头的预处理指令（属性与定义）

`#` 行必须**紧跟在函数声明行之下**，否则警告 `InvalidSharp`（`Runtime/Script/Loader/ErbLoader.cs:384-394`）。所有 `#` 指令由 `LogicalLineParser.ParseSharpLine`（`Runtime/Script/Parser/LogicalLineParser.cs:17-276`）分发。`#` 之后的指令名本身不做宏展开（源码注释「#～自体にはマクロ非適用」，`:20`）。

文档把 `#` 指令分成三类：**属性**（决定函数规格）、**定义**（声明变量名/规格）、**特殊区块**（上一节的 `[XXX]`）。

### 事件函数专用属性：#ONLY / #PRI / #LATER / #SINGLE

这四个属性在 ecd/zh 文档中只有 `#ONLY` 被记载，`#PRI`/`#LATER`/`#SINGLE` 未被记载，但源码完整支持（`Runtime/Script/Parser/LogicalLineParser.cs:31-139`）：

| 属性 | 规则（源码） |
| --- | --- |
| `#ONLY` | 仅事件函数可用。设置后同名的其他事件函数（含其他 `#ONLY`）不再执行；同一名下已出现过 `#ONLY` 再声明会警告 `AlreadyDeclaredOnly`。与 `#PRI`/`#LATER`/`#SINGLE` 同用时，后者被清除并警告 `BeIgnorePri/Later/Single`（`:124-138`）。 |
| `#PRI` | 仅事件函数可用。提前执行组。与 `#LATER` 同用会警告 `PriWithLater` 但两者都生效。 |
| `#LATER` | 仅事件函数可用。延后执行组。 |
| `#SINGLE` | 仅事件函数可用。运行时若该事件函数以 `RETURN 1` 结束，则**跳过后续所有组**（见下）；与其他属性同用时警告但不禁用。 |

执行顺序由 `LabelDictionary.SortLabels`（`Runtime/Script/Data/LabelDictionary.cs:58-125`）决定：同名事件函数被分成 4 组按序执行——`onlylist → prilist → normallist（无 #PRI/#LATER 者）→ laterlist`；`#PRI`+`#LATER` 双重注册的函数会在 pri 与 later 两组各执行一次（注释「eramakerの仕様」）。运行时 `Runtime/Script/Process.State.cs:398-405`：`#ONLY` 函数执行完即 `FinishEvent()` 终止整个事件链；`#SINGLE` 函数若 `RETURN 1` 则 `ShiftNextGroup()` 跳到下一组，否则与普通函数一样 `ShiftNext()` 逐个执行。

```text
// Process.State.cs:398-405（伪代码）
事件函数 RETURN 时:
    if called 是 #ONLY:   FinishEvent()        // 整个事件链结束
    elif called 是 #SINGLE 且 ret == 1: ShiftNextGroup()  // 跳过其余组
    else:                 ShiftNext()          // 继续下一个同名函数
```

### #FUNCTION / #FUNCTIONS（表达式内函数）

- `#FUNCTION`（数值型）/`#FUNCTIONS`（字符串型）把普通函数变成表达式内函数：函数体必须以 `RETURNF <表达式>` 结束，可在一切表达式中以 `FUNC(参数)` 形式调用。详见 language/自定义表达式内函数 相关主题。
- 源码规则（`Runtime/Script/Parser/LogicalLineParser.cs:140-193`）：函数名不能以数字开头；系统函数（`Depth == 0`）不能声明为表达式内函数（警告 `UseSharpInSystemFunc`）；重复声明同型警告、异型警告；与 `#PRI`/`#LATER`/`#SINGLE`/`#ONLY` 同用时后者被清除并警告。设置后 `IsMethod = true`、`Depth = 0`（被当作最优先解析的函数）、`MethodType` 设为 `long`/`string`。

### #LOCALSIZE / #LOCALSSIZE

- 为本函数单独指定 `LOCAL`/`LOCALS` 的元素数（`Runtime/Script/Parser/LogicalLineParser.cs:194-249`）：参数必须是**常数项**（含宏展开后）且 `> 0`、`< int.MaxValue`，否则警告并忽略；含变量时同样无效。
- 事件函数中指定会被**警告并忽略**（`EventFuncIgnoreSpecified`，`:204-208`）。
- 与文档差异：文档称「对事件函数使用时采用最先被执行的那个函数的设置（ver1800）」；现源码改为直接忽略，而实际 `LOCAL` 大小取**同名事件函数组内所有函数声明的最大值**（与 `VariableSize.csv` 默认值取较大者，`Runtime/Script/Data/LabelDictionary.cs:81-89`）。

### #DIM / #DIMS（变量声明）

- 函数内（紧跟 `@` 行）声明**私有变量**：`#DIM 名, 元素数...`（数值）/`#DIMS 名, 元素数...`（字符串）。变量名与既有标识符冲突时警告 `VarNameAlreadyUsed`；行尾多余字符警告 `ExtraCharacterAfterSharp`（`Runtime/Script/Parser/LogicalLineParser.cs:250-264`）。
- 关键字由 `UserDefinedVariableData.Create`（`Runtime/Script/Data/UserDefinedVariable.cs:32-`）解析：`STATIC`（默认，随存档外变量存续）/`DYNAMIC`（函数退出即销毁）互斥；`REF`（引用型）；`CONST`（常量）；`SAVEDATA`（随存档保存）；`CHARADATA`（角色变量）；`GLOBAL`（全局变量，跨存档，配 `SAVEGLOBAL`/`LOADGLOBAL`）。关键字之间存在详细互斥表（如 `CONST` 不能与 `CHARADATA`/`GLOBAL`/`SAVEDATA`/`REF`/`DYNAMIC` 同用等）。
- ERH 中使用则为**广域变量**（见下节）。变量语义详见 language/用户自定义变量相关主题。

### #DEFINE（宏）

只能在 ERH 中定义（见下节）；ERB 内的 `#` 行没有 `DEFINE` 分支，落到 `default` 会得到「无法解释的 # 行」警告（`Runtime/Script/Parser/LogicalLineParser.cs:265-267`）。

## 头文件（ERH）

- `ERB` 文件夹中扩展名为 `*.ERH` 的文件，用于记载需要先于 ERB 处理的内容：`#DIM`/`#DIMS` 广域变量与 `#DEFINE` 宏。**不能书写其他行**——非 `#` 行直接抛 `NotStartedSharpLineInHeader`（`Runtime/Script/Loader/ErhLoader.cs:100-101`）；`#` 后的未知指令抛 `UnknownPreprocessorInSharpLine`（`:128-129`）。
- 源码中 ERH 的 switch 还接受 `#FUNCTION`/`#FUNCTIONS`（`Runtime/Script/Loader/ErhLoader.cs:115-118`），但对应处理函数直接抛 `NotImplCodeEE`（`:385-391`），即语法上预留、功能未实现。
- ERH 中声明的广域变量：所有 ERB 内可引用；没有 `DYNAMIC`/`STATIC` 之分，不能用 `REF`，但可用 `CONST`；最高 3 维；不指定元素数即元素数 1。`SAVEDATA`/`CHARADATA`/`GLOBAL` 关键字可组合使用（`CHARADATA+SAVEDATA`、`GLOBAL+SAVEDATA`），语义同上节。
- ERH 的 `#DIM` 行先入队、全部 ERH 读完后统一解析（`ErhLoader.analyzeSharpDimLines`，`:270-359`），允许元素数为常数表达式（其中变量引用可在后续行中再定义，解析失败会重试一轮）。

## 宏（#DEFINE）

宏是把 ERB 代码中的字符串替换为预先定义好的另一串字符串的功能（参考 C/C++ `#define`；与 F1～F12 键盘宏无关）。在 ERH 中定义后适用于所有 ERB。

### 定义与展开

```erb
; <*.ERH>
#DEFINE FIVE 5          ; 行末注释会被剥掉，不计入宏体
#DEFINE HOGE            ; 空宏（用于 [IF HOGE] 判断）
#DEFINE HOGERA  LOCAL + MY_FUNC(X, Y)

; <*.ERB>
X = FIVE + FIVE         ; 展开后 X = 5 + 5
```

- 展开是**词法单位级别**的：一行经 `LexicalAnalyzer.Analyse` 切成词后，`expandMacro` 把命中的标识符 `IdentifierWord` 整体替换为宏体的词序列，反复应用直到无法应用（`Runtime/Script/Parser/LexicalAnalyzer.cs:1027-1046`）。所以是「按原样展开右侧字符串」：`#DEFINE SIX 1 + 5`、`#DEFINE NINE 8 + 1` 时 `X = SIX * NINE` 展开为 `X = 1 + 5 * 8 + 1`，结果 42。
- 单词宏（宏体恰为一个标识符）有快速通道 `DefineMacro.IDWord`（`Runtime/Script/Data/DefineMacro.cs:14-16`）；单行内展开次数上限 `MAX_EXPAND_MACRO = 100`（`Runtime/Script/Parser/LexicalAnalyzer.cs:68, 1032-1035`），超过即报「疑似自我引用/循环引用宏」。

### 限制与错误行为

- 宏只在**表达式**中展开：`PRINT FIVE` 打印的是文本 `FIVE`（`PRINT` 正文不走表达式解析）。
- **行首第一个单词不展开**：命令文行首的标识符由 `ReadFirstIdentifierWord` 读取，1.808a3 起明确取消了对它的宏展开（「命令の置換禁止」，`Runtime/Script/Parser/LexicalAnalyzer.cs:386-410`）。因此不能把宏替换成指令——`#DEFINE MY_PRINTL PRINTL` 后写 `MY_PRINTL ～～` 会因行首无法解析为命令而报错。
- 替换目标不能是赋值运算符或含赋值运算符的表达式（`#DEFINE HOGE =`、`#DEFINE PUGE X = 1` 会出错）：这类宏展开进表达式后，赋值运算符在表达式求值处非法。
- 括号必须在宏体内部闭合：`#DEFINE HOGE ( X +` 在定义时就被 `Analyse` 的括号配对检查拒绝（`NotCloseBrackets`，`Runtime/Script/Parser/LexicalAnalyzer.cs:1019-1026`）。
- 宏不适用于：`*.csv`、`*.ERH` 的指令名/属性名/行首记号、`[SKIPSTART]` 等区块行 token、`#DIM`/`#FUNCTION` 等 `#` 后的指令名本身、`@EVENTFIRST` 的 `@` 记号——这些都用不做宏展开的 `ReadSingleIdentifier` 读取（`Runtime/Script/Loader/ErbLoader.cs:367-369`、`Runtime/Script/Parser/LogicalLineParser.cs:20`）。但 `#` 之后的**变量名与元素数**（`#DIM HOGE, FIVE` 中的 `HOGE`、`FIVE`）是普通标识符，会被展开。
- 函数型宏（`#DEFINE FOO($1) ...`）：定义端的参数解析代码存在（`Runtime/Script/Loader/ErhLoader.cs:175-247`），但 1.808a3 起**封印**——定义完成前直接抛 `CanNotDeclaredFuncMacro`（`:249-250`）；展开端的 `expandFunctionlikeMacro`（`Runtime/Script/Parser/LexicalAnalyzer.cs:1052-`）也因无法定义而不可达。
- `[IF XXX]`/`[ELSEIF XXX]` 以宏字典中是否存在名为 `XXX` 的宏为条件，空宏可用于此目的。

## 装载后的三轮解析

函数体在装载期还要经过三轮处理（`ErbLoader.ParseScript`，`Runtime/Script/Loader/ErbLoader.cs:684-829`）：

1. `setArgument`：按配置 `NeedReduceArgumentOnLoad` 预先解析命令参数；
2. `nestCheck`：检查 `IF/ELSEIF/ELSE/ENDIF`、`REPEAT-REND`、`SELECTCASE-CASE`、`PRINTDATA-ENDDATA`、`TRYCALLLIST-FUNC-ENDFUNC`、`NOSKIP` 等块状语法的配对与嵌套，并建立 `JumpTo` 连接；
3. `setJumpTo`：为流程控制指令设置跳转目标，同时发现调用了未定义函数的行（按配置警告 `FuncNeverCalled` 等）。

这三轮与预处理指令本身无直接关系，但决定了「定义」阶段发现错误的时机与报错形态。

## 与源码的差异/备注

1. **#PRI / #LATER / #SINGLE 文档缺失**：ecd 与 zh 的《函数与预处理指令》只记载了 `#ONLY`、`#FUNCTION`、`#FUNCTIONS`；`#PRI`/`#LATER`/`#SINGLE` 三个事件函数属性在源码中完整实现（`Runtime/Script/Parser/LogicalLineParser.cs:31-139`、`Runtime/Script/Data/LabelDictionary.cs:95-101`、`Runtime/Script/Process.State.cs:398-405`），本文按源码补记。
2. **#LABELFLAG 不存在**：任务描述中提到的 `#LABELFLAG` 在两套文档与全部源码中均不存在（全仓库检索无结果），非 Emuera 指令。
3. **#ONLY 与其他属性的组合**：文档只说「`#ONLY` 存在时只执行这一个」；源码上 `#ONLY` 会主动清除同函数的 `#PRI`/`#LATER`/`#SINGLE` 并逐项警告，且跨文件重复 `#ONLY` 会警告 `AlreadyDeclaredOnly`。
4. **#LOCALSIZE 对事件函数的行为**：文档称「事件函数采用最先被执行的那个函数的设置（ver1800）」；现源码对事件函数的 `#LOCALSIZE` 直接警告并忽略，组内实际 `LOCAL`/`LOCALS` 大小取同名事件函数的最大声明值与 `VariableSize.csv` 默认值的较大者（`Runtime/Script/Data/LabelDictionary.cs:81-89`）。
5. **行中注释**：ecd《Eramaker 的 ERB 文件格式》说「不支持行尾注释」，这是 Eramaker 规则；Emuera 1.807 起 `Analyse` 支持行中 `;` 之后作注释（`Runtime/Script/Parser/LexicalAnalyzer.cs:995`）。
6. **ERH 的宏展开**：文档称「与 `*.ERB` 中的 `#DIM` 不同，这里（ERH）不会展开宏」「宏只适用于 `*.ERB`，不适用于 `*.ERH`」；本仓库源码中 ERH 的 `#DEFINE` 宏体与 `#DIM` 行同样经 `LexicalAnalyzer.Analyse → expandMacro`（`Runtime/Script/Loader/ErhLoader.cs:123、177`），在同一 ERH 文件内先定义的宏对后续 `#DIM` 行是生效的。差异可能源于实现版本（1.822 起把 ERH `#DIM` 改为先 `Analyse` 后入队），目标 C# 版本的行为应另行实测确认。
7. **ERH 中的 #FUNCTION/#FUNCTIONS**：文档说 ERH 只能写 `#DIM`/`#DIMS`/`#DEFINE`；源码 switch 还接受这两个 token，但立即抛 `NotImplCodeEE`（未实现），实际效果与「不允许」一致。
8. **函数型宏**：文档完全未提及；源码有完整定义/展开代码但在 1.808a3 被封印（`Runtime/Script/Loader/ErhLoader.cs:249-250`），用户不可用。
9. **`{`～`}` 行连接**：为 EE（EmueraEE 分支）扩展，两套文档的 ERB 格式篇（Eramaker 视角）均未记载；`ReadFirstIdentifierWord` 取消行首单词展开（1.808a3）也与旧版行为文档未更新处相关。
10. **宏展开上限**：文档只说「反复展开一定次数后报错」；具体次数为单次 `Analyse` 内 100 次（`Runtime/Script/Parser/LexicalAnalyzer.cs:68`）。
11. zh 套件三篇与 ecd 三篇内容一致（zh 为同一 Wiki 的早期机翻版本，含重复行与「1 2 3」类排版噪声，无实质规则差异）；zh 末尾标注 Last Updated 2021/9/30，ecd 为其后修订版。
