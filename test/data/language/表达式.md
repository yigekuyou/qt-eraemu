# 表达式

> 来源：ecd/Expression.md（表达式内函数 exmeth）、ecd/ERB_Expressions.md（ERB 的表达式）；zh/Expression.md、zh/ERB_Expressions.md 交叉核对。
>
> 运算符的完整语义与优先级细节另见 [运算符.md](运算符.md)。

## 概述

表达式是"能算出结果的东西"，出现在赋值语句右值、命令参数（`IF`/`SELECTCASE`/`CALL` 实参等）与 FORM 字符串嵌入段中。EraBasic 只有两种值类型——64 位有符号整数与字符串，表达式解析器（`ExpressionParser.reduceTerm`）把词法单元流归约为一个带类型（`long`/`string`）的语法树项（`AExpression`），求值时通过 `GetIntValue`/`GetStrValue` 取值。表达式里可以引用变量、调用式中函数（内置或 `#FUNCTION` 用户定义）、以及使用 `#DEFINE` 宏展开后的内容。

## 值类型

### 整数

- 64 位有符号整数（`long`），**没有小数类型**；`5 / 3` 的结果是 `1`（整除）。C# 在除数为 `0` 时抛出错误；当前 Qt/C++ 求值器仍返回 `0`，这是已知实现差异。
- 字面量支持三种进制：十进制直接书写（可带 `+`/`-` 前缀）、`0x` 十六进制、`0b` 二进制；**不支持八进制**（源码注释明确"8進法は互換性の問題から採用しない"）。
- 十进制/十六进制尾数后还可跟 `e`/`E`（10 的幂）或 `p`/`P`（2 的幂）指数记法，如 `1e3` = 1000（文档未记载，见实现）。结果超出 64 位范围时报错。
- 小数写法（`1.5`）不能出现在一般表达式中；`double` 只有 `TIMES` 命令的第二参数使用。

### 字符串

- 字面量用双引号包围：`"abc"`。支持转义 `\s`（半角空格）、`\S`（全角空格）、`\t`、`\n`，`\` 后接其他字符则原样保留该字符。
- 单引号 `'...'` 仅在 `HTML_PRINT` 解析（`LexAnalyzeFlag.AllowSingleQuotationStr`）和 `PRINTV` 参数中可用；在赋值语句里 `'` 是字符串赋值运算符 `'=` 的一部分（见下）。
- 格式化字符串（FORM 字符串）以 `@"` 开头：`@"金币：{MONEY}"`，内部语法见下节。
- 字符串变量赋值时，若配置 `SystemIgnoreStringSet`（SSTR）开启则直接报错（ArgumentBuilder.cs:1148-1153）。

### 类型互转

整数与字符串**不会自动转换**：

- 数值 + 字符串、数值与字符串比较，解析期就抛 CodeEE（`OperatorMethodManager.ReduceBinaryTerm`，OperatorMethod.cs:140-176）。
- 显式转换函数：`TOSTR(value, format)`（数值→字符串）、`TOINT(str)`（字符串→数值）、`ISNUMERIC(str)`（判断可否转数值）。

```erb
#DimS Msg = "金币："
Msg = Msg + TOSTR(MONEY)
```

## FORM 语法

FORM 字符串（`@"..."` 及 `PRINTFORM` 系命令的原始文本）中可以嵌入表达式：

- `{数值表达式}`：展开为整数的十进制表示；
- `{数值表达式, 宽度, LEFT|RIGHT}`：按宽度对齐（**省略第三参数时默认 RIGHT**，即左侧补空格）；
- `%字符串表达式%`：展开为字符串；
- `%字符串表达式, 宽度, LEFT|RIGHT%`：按显示宽度对齐（全角字符按 2 半角宽计）；
- `\@条件 ? 文本A # 文本B\@`：字符串三元运算符（见下）；
- 三连符号：`***`→TARGET 的 NAME、`+++`→MASTER 的 CALLNAME、`===`→PLAYER 的 CALLNAME、`///`→ASSI 的 NAME、`$$$`→TARGET 的 CALLNAME。可用配置 `SystemIgnoreTripleSymbol` 禁用。

```erb
PRINTFORM 金币：{MONEY}
PRINTFORM 姓名：%NAME:0%
PRINTFORM [{MONEY,10,LEFT}]
PRINTFORM 对方是%%——不对，是%CALLNAME:TARGET%
```

## 三元运算符

```erb
; 数值：直接用 ? #
变量 = 条件 ? 为真时的值 # 为假时的值
; 字符串：整体包在 \@ ... \@ 中
变量 = \@条件 ? 为真时的文本 # 为假时的文本\@
```

- 等价于 `IF 条件 ... ELSE ... ENDIF` 的赋值。
- `#` 不能省略；但源码实现中 `\@～?\@` 缺 `#` 只产生**警告**并把假值当作空串 `""` 处理（LexicalAnalyzer.cs:1287-1293 → StrForm.cs:103-104），与文档"不能省略"的表述有出入。
- 字符串三元本质上是在 FORM 解析层完成的（`\@` 在表达式开头也会被词法分析器接受：LexicalAnalyzer.cs:984-991），运行时逻辑同 `TernaryIntStrStr`。
- 求值是惰性的：条件非 0 时才取真值分支（`Runtime/Script/Statements/Expression/OperatorMethod.cs:799-816` 用 C# 三目）。未加括号的嵌套 `?` 按 C# 语法会报错；嵌套时使用 `A ? (B ? C # D) # E`。

## 运算符与优先级（概要）

从高到低（详细语义见 [运算符.md](运算符.md)）：

| 分类 | 符号 |
|---|---|
| 单目 | `~` `!` `-`（负号）`+` `++` `--` |
| 算术 | `*` `/` `%`；`+` `-` |
| 位移 | `<<` `>>` |
| 比较 | `<` `>` `<=` `>=`（高）；`==` `!=`（低） |
| 位 | `&` `^` `|` |
| 逻辑 | `&&` `||` `^^` `!&` `!|` |
| 三元 | `? … #` |
| 赋值（仅语句级） | `=` `'=` `+=` `-=` `*=` `/=` `%=` `<<=` `>>=` `&=` `|=` `^=` `++` `--` |

- 比较结果是 `1`（真）/`0`（假）。
- `&&` `||` **短路求值**：左项为 0/非 0 时右项不再求值（OperatorMethod.cs:525、542）。`^^`、`!&`、`!|` 都会求值两侧。
- `==`/`!=` 的优先级低于 `< > <= >=`（源码 0x60 vs 0x65，注释"不等価優先"），因此 `A == B < C` 解析为 `A == (B < C)`。当前 C++ 运算符表保持该优先级。
- 赋值运算符不是表达式运算符：它们只在赋值语句（`Runtime/Script/Parser/LogicalLineParser.cs:558-588` 识别为 `SET` 指令）中出现，表达式内部出现 `=` 会报错（ExpressionParser.cs:435-439）。

```text

  ExpressionParser.cs:510-686 TermStack
    遇到值   -> 压栈，state=1
    遇到运算符:
      前置单目在值之前（state=0）要求 IsUnary

```

## 括号

括号强制先算：`(A + B) * 2`。实现上是递归调用 `reduceTerm` 生成一个子项（ExpressionParser.cs:464-474），括号不匹配在词法/语法两层都会报错（LexicalAnalyzer.cs:1017-1027）。

## 表达式中可用的东西

### 变量

- 标识符先按变量名解析（`ExpressionParser.reduceIdentifier`，ExpressionParser.cs:272-281 → `VariableParser.ReduceVariable`），数组下标用 `(...)` 或 `[...]`，角色变量如 `CFLAG:(角色编号):(属性编号)`。
- 变量后面跟 `(` 或 `[` 且不是变量时，按式中函数调用处理（ExpressionParser.cs:249-271）；`[` 函数调用在 1810 版后被明确"大概永远不会实现"而直接报错（ExpressionParser.cs:252-253）。
- `VAR`/`VARS`/`CVAR`… 系"关联数组"变量支持用裸名字做键：名字若在 CSV/用户定义名单里则当作字符串字面量处理（ExpressionParser.cs:286-313）。
- `++`/`--` 只能作用于**非 const 变量**（OperatorMethod.cs:85-91）。

### 式中函数（内置）

表达式中可直接调用内置函数（Emuera 1.712 新增"表达式内函数/方法"）：

```erb
A = ABS(A)
IF STRLENS(STR:0) > A
    LOCALS:0 = %SUBSTRING(STR:0, A, 1)%
ENDIF
```

- 无参函数也必须带 `()`（如 `GETTIME()`），以区别于变量。
- 参数可省略（有默认值）：`SUBSTRING(RESULTS)` 等价 `SUBSTRING(RESULTS, 0, -1)`；也可留空占位：`RAND(, 100)`。
- `var` 类型参数表示"传变量本身"（如 `FINDCHARA(TALENT, ...)`），`?` 表示类型由其他参数决定，`...` 表示可变长参数（如 `MAX(A,B,C,...)`）。
- 函数定义签名中的类型检查：`#DIM` 定义函数参数带初始值时，`ReduceArguments(..., isDefine: true)` 会解析 `=` 默认值并检查左右类型一致（ExpressionParser.cs:101-126），缺省补 `NullTerm(0)`/`NullTerm("")`。
- 内置式中函数完整清单（`ABS` `MAX` `POWER` `STRLENSU` `SUBSTRING` `BARSTR`…）见 commands/ 与 functions/ 目录，此处不重复。

- 展开在 `Analyse` 返回前统一执行（LexicalAnalyzer.cs:1028-1030），因此表达式中出现宏是安全的。

### 关键字

- `TO`、`IS` 仅在 `SELECTCASE` 的 CASE 条件中有效；普通表达式里出现 `TO`（未允许时）或 `IS` 直接报错（ExpressionParser.cs:407-415）。
- `px`（EM 私家版 HTML 参数扩展）：在 HTML_PRINT 参数表达式中作为长度单位终止符（ExpressionParser.cs:417-422，`TermEndWith.KeyWordPx`）。

## 求值与常量折叠

表达式在**装载期**会被"重构"（Restructure）：常量子式折叠成 `SingleTerm`（Term.cs:22-34、FunctionMethodTerm.cs:31-51），`CanRestructure` 的运算/函数在参数全为常量时直接算出结果。运行期才执行的部分（变量引用、有副作用的用户函数等）保持树结构，按 `GetIntValue`/`GetStrValue` 递归求值。因此：

- 同一表达式中变量与函数的求值顺序在语言层面是未定义的，不要在式中函数里写副作用；
- 短路求值会跳过右项的函数调用（ecd/Custom_Expression.md 的"短路逻辑导致调用省略"）。

## 与源码的差异/备注

1. **整数指数记法**：`1e3`、`1p10` 这类写法在 LexicalAnalyzer.ReadInt64（138-195 行）中受支持，两套文档均未提及。
2. **`\@…?…\@` 缺 `#`**：文档说"不能省略"，实现是警告 + 假值取空串（LexicalAnalyzer.cs:1288-1293）。
3. **ecd/ERB_Expressions.md 优先级表**把赋值运算符列为表达式的一部分（`=`、`+=`…）；实现中赋值不是表达式运算符，只在语句层（`SET` 指令）处理。表中"位运算符"一行也漏掉了 `^`（BitXor，优先级介于 `&` `|` 同级，OperatorCode.cs:38）。
4. 文档说字符串对齐"按宽度"，实现中 `%…%` 的宽度按显示宽（全角=2）计算，`{…}` 按字符数计算（StrForm.cs:239-263）。
5. ecd/Expression.md 的内置式中函数清单是 wiki 旧版快照，实际实现中的函数更多（如 `GETBIT`/`CBRT`/`GROUPMATCH` 之后的版本均有新增），以 functions/ 目录生成的单条文档为准。
6. zh 套件的 Expression.md 与 ERB_Expressions.md 正文为空（仅导航骨架），无法逐条交叉核对；本页以 ecd 为准。
